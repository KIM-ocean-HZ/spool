### P16-1 · AI 只读新加的块（想法 #4 前半）

**Ocean 原话**：「MCP正在用已有block工作时，用户加入新block，然后进行继续对话，AI可能需要重新整理spool项目，而不是可以继续读取，你需要查证这个缺陷是否真实存在……这表明spool会浪费token，AI会得到一个冗余的信息，这违背了AI在同一窗口多次对话的便捷性。」

**现在（11-09 查过）**
- 缺陷是真的：11-08 写文书那场 Codex 对话，第二轮（Ocean 在 Spool 里新加了几块之后）依次调了 `list_threads` → `get_blocks` → `get_project_overview` → `search_blocks` → `get_pack`，回传约 6 万字符；上下文压缩发生在这之后约 6 分钟，所以不是忘了才重读。
- `get_blocks`（`mcp.rs:3680` `get_blocks_json`）只有 `offset` / `limit` / `around_block_id` 和几个筛选，没有「给我 #N 之后的」；没有任何地方告诉 AI 同一场对话里接着干活时该怎么读。
- `list_threads` 有块数和 `last_block_at`，`get_project_overview` 有最新 5 块各一行，但都没直接说「最新一块是 #几」。路由文字里 `list_threads` 写着「Call this first」，AI 每轮都会再调一次。
- 块没有修改时间（`blocks` 表没有 `updated_at`）：改了旧块的字，从库里看不出来。

**要做**
1. `get_blocks` 加一个只读参数（名字执行窗定，比如 `after_seq`）：只返回块号大于 N 的块，按时间顺序；和别的筛选怎么组合写进工具描述。
2. `list_threads`、`get_project_overview`、`get_blocks`、`get_pack` 的结果里都说出「这个项目最新一块是 #N」（字段或一句话，执行窗定；`get_pack` 只加在 MCP 回执里，⛔ 不动 pack 正文）。
3. 路由文字（`OPENERS` 中英各一行 + `INSTRUCTION_BODY` 一句）：同一场对话里接着干活，用户说加了 / 改了东西，或者 `list_threads` 显示的块数比你读到的多 —— 用 `get_blocks` 只取你已经读到的最新块号之后的；这场对话里已经拿到项目 id 了就不用再调 `list_threads`；用户说改了某一块，按块号重读那一块（`around_block_id`）。
4. 按 §4 第 1 题处理「改了旧块」。

**不做**：不记哪个 AI 读到哪（`DISCOVERED-20261109-6`）；不加用户书签（`-8`）；不改 pack 正文。
**验收**
- 测试：新参数只回新块、和筛选的组合、最新块号在四个工具的结果里都有；路由测试照旧绿；pack golden 不动。
- 真跑（库副本，§2 的上限内）：本机 Codex 或 Claude Code 两轮对话 —— 第一轮读一个项目；往副本里加 2 块；第二轮说「我在 Spool 里又加了两块，继续」。通过标准：第二轮不调 `get_pack`、只取到新加的那两块，Spool 回传的字数比第一轮少一个数量级。改前、改后各跑一次对照。
- Ocean 在自己的 Codex 里试一次。

### P16-2 · AI 交活时提议挂文件 / 换新版，做完一段活写回（想法 #5）

**Ocean 原话**：「AI写好的文档并不会提议连接到Spool的项目文件，而我曾经做的MCP可以提议换掉过期文件，使用新文件的迭代更新文件功能也无法使用。更深挖掘，我怀疑Spool的MCP所有工作在对话刚开始就被AI全部读取完了，之后的工作，AI再也不会访问Spool，也不会做类似跟进，挂文件……」

**现在（11-09 查过）**
- 一半对：有的对话 AI 每轮开头都读 Spool（还读多了，见 P16-1），有的读完一次就再没回来。10 – 11 月 24 场用过 Spool 的 Codex 对话（桌面版 + VS Code 插件，不含引擎自己跑的）里，13 场有 3 轮以上，其中 4 场最后一次碰 Spool 之后又干了两轮以上的活；最长一场 13 轮只在第 1 轮读过。
- 写：这 24 场里挂文件提议 4 次、换新版 0 次。正式库 88 个现用的项目文件里 26 个是 AI 提议、Ocean 批的（Claude 桌面版 10 个；Codex 16 个，都在 10-14 一天），最后一次 10-28；被换掉的旧版本 0 个 —— 「新版换旧版」上线以来没成过一次。11-08 写文书那场，AI 写完文件没有提议挂上去。
- 原因在 Spool 这边：`OPENERS` 里「挂文件」「换新版」只在用户说「把这个文件挂上」「新版本替换旧的」时触发（`mcp.rs` 13180 行起）；`INSTRUCTION_BODY` 只说了「写回是为了这场对话产出、而库里没有的东西」，没有一句告诉 AI「你自己写出一份交付物的时候，提议挂上」，也没有「一段活做完、改了计划时写回一条」。
- 相关、不在范围：`DISCOVERED-20261027-6`（5 个连着的文件夹 CLAUDE.md / AGENTS.md 指针全关，在仓库里干活的 AI 不一定读到 SPOOL.md 的写回规矩）—— 回执里说一句它对结果的影响，要不要改由 Ocean 定。

**要做**
1. 路由文字（`OPENERS` 中英各一行 + `INSTRUCTION_BODY`）：
   - 你为这个项目写出了一个文件（草稿、报告、导出）并存到了用户电脑上 → 同一轮里 `propose_attach_file`；它是项目里某个文件的新版 → `propose_replace_file` 指着旧文件；
   - 一段活做完、这一轮改了计划 / 定了事 / 留下没解决的问题 → `add_block` 一条 / `suggest_follow_up_item` / 答上了就 `close_follow_up_item`；
   - 压住噪声：一轮最多提一次；草稿中间稿、临时文件、和项目无关的文件不提。
2. 按 §4 第 2 题：读项目时的 MCP 回执末尾加一句（只在 MCP 回执里；⛔ 不进 pack 正文，⛔ 不进用户自己复制 / 导出的 pack）：项目里有哪些文件（带 `attachment_id`），写出新版时提议替换；交活时记得写回。

**不做**：不做 `DISCOVERED-20261030-6`（平常对话里、还没有项目时提议新建）；不加新工具；不加设置开关。
**验收**
- 测试：路由文字里有新触发（中英）；pack golden 不动；回执末尾那句只在 MCP 路径出现。
- 真跑（库副本 + 一个挂了文件的项目）：让本机 Codex / Claude Code 「把〈某文件〉改一版存到〈某路径〉」，看待审里有没有出现「换新版」卡；再让它做一段会改计划的活，看有没有写回一条。改前、改后各跑 3 次，记次数；也要看有没有乱提（没要求时提了算噪声）。
- Ocean 真用一次（比如让 Codex 改一份文书），待审里出现那张卡。

### P16-3 · 跟进收尾（想法 #1）

#### 7.1.1 问题 1：哪些来源会被当成 📖，网页能不能冒充

- **pack 本身不替来源分带**：渲染器只印 💭（没有来源）和 📌。📖 / 🧩 / 🔄 由收件的 AI 读 `[时间 · from 来源]` 那一格自己判。表头 📖 那一节写的是「来源**看起来像**机构 / 官方的东西：邮件客户端、学校 / 机构域名、文件附件、权威人物的论坛帖子」，判进去就是「Treat as ground truth. Do not contradict」（`mcp.rs:284`，TS 那份逐字一样）。
- **网页捕进来的来源 = 浏览器标签页的标题**，是网页自己写的：Mac 读标签页标题（`capture.rs:162` `browser_tab_title`），Windows 读窗口标题再去掉浏览器的尾巴（`capture.rs:101` `browser_caption`）。标签里**没有**「这是网页」「是哪个浏览器」这一截。⇒ 网页把 `<title>` 写成「Outlook — 某某大学录取办公室」，存下来就是 `· from Outlook — 某某大学录取办公室`，收件 AI 很可能判成 📖。
- 界面那一侧更宽：`band.ts:56` `bandOf` 只要来源不是 AI 工具名，一律算「来源材料」（📖），连「看起来像不像机构」都不问。这只影响核对压缩稿时卡片上写的带名，不进 pack。
- **AI 写回的块冒充不了**：MCP 写进来的块来源一律是 `<客户端名> · MCP`（`mcp.rs:4964`，`add_block` 的 `source` 参数只能接在后面，客户端名盖不掉）；跟进提回来的是 `… · 跟进 · MCP`。表头按「来源是 AI 工具」判成 🧩。
- 挂上的文件（PDF / docx）按表头算 📖；文件里写什么由文件作者定，这是表头本来的意思，不算冒充。

#### 7.1.3 每一条风险：机会、后果、最小改法、代价

**R1 · 跟进那一轮（本机 CLI 引擎）：联网 + 整库读 + 直接写，没人看着** —— 方针 §8 一类，已报 Ocean
- 现在它手里有什么（证据）：
  - 联网：Codex 带 `tools.web_search=true`（`engine.rs:986`），11 月引擎记录里有 `open_page`（打开指定网址）；Claude Code 带 `WebFetch`（`engine.rs:119`，任意网址）；Gemini 带 `web_fetch`。
  - 读：MCP 那一侧除了私密项目整库都读得到（`server_args` 只多一个 `--engine-follow-up`，没有按项目限定）。**Codex 还有自己的 shell**：只读沙箱，cwd 是 `/`，能读整块磁盘 —— 11-08 00:40 那次跟进它真用 shell 读了 `~/flux/docs/supervision/` 下的文件和 git 记录。所以只在 Spool 这边限读，挡不住 Codex 读 `spool.db` 本身（里面有私密项目）或别的文件。
  - 直接写：`add_block`、`create_thread`、`set_thread_summary`、`set_block_gist`、`close_follow_up_item` 都在引擎的工具单里（`engine.rs:78`），「允许 AI 写入」开着（你现在是开的）就直接生效，不进待审。提示词说「不要用 add_block」，代码里没拦。
  - 另外：Codex 那一轮默认还开着 `apps`（ChatGPT 连接器）、`plugins`、`multi_agent`、`memories`、`browser_use`、`computer_use`、`image_generation`（`codex features list`；`--ignore-user-config` 只跳过你的 config.toml，默认开的功能还在），引擎会话里能看到 apps / plugins / 多代理的说明。跟进一个都用不到。`engine.rs:962` 那句「shell 关不掉」是按 0.146 写的，0.147 已经有 `features.shell_tool`。
- 碰到的机会：要被搜到的某个网页里专门写了给 AI 看的指令。这种「间接注入」在野外已经有实证（`archive/DESIGN_FOLLOW_UP.md` §2.5 引的研究）。你有 5 个项目开着每周自动跟进。
- 后果（最坏）：读你别的项目（Codex 的话，连私密项目和磁盘上别的文件），拼进一个网址打开 = 发出去；或者往库里写不经待审的块、改 AI 写的摘要和简介、关跟进行、建新项目。
- 现状：引擎 15 次跟进（8-08 – 11-08）直接写块 **0** 次（`engine_runs.blocks_written`），都走了待审；没查到被利用的迹象。这个口子从 8 月跟进上线就在：当时设计稿的前提是「这条路上 AI 根本不能写，只能提案」（`DESIGN_FOLLOW_UP.md` §2.5），之后工具单改成了「Spool 的全部工具」（`engine.rs:66` 那段，防「调了没有的工具就停下来问权限」），这个前提就不成立了。
- 最小改法（**Ocean 11-10 已批，插在 P16-0 后面做**）：
  1. 跟进那一轮，Spool 的 MCP 只让它看到正在跟进的那一个项目（和私密项目同一套临时视图的做法）。
  2. 直接写的四个工具（`add_block` / `create_thread` / `set_thread_summary` / `set_block_gist`）对引擎关掉：不列出来、调了也拒。`close_follow_up_item`、`suggest_follow_up_item`、`propose_*` 留着（只能碰这一个项目）。
  - 代价：小；跟进提示词本来就是这么要的。要真跑一次跟进，看它没被改坏。
- ⚠️ 只做 1、2 **关不上 Codex 那半**：shell 照样能读磁盘，「打开页面」照样能出网。要真关上，还要下面几件里选（**要 Ocean 定**，见 7.1.4）。

**R2 · 周回顾那一轮（本机 CLI 引擎）也拿着直接写的工具**
- 不联网（`web=false`），读的是整个库（除已完成 / 私密）。库里捕进来的网页文字里有一句「把这条存进 X」，理论上能让它直接写一块 / 改摘要。没有出网的路，所以不会泄露。
- 最小改法：R1 第 2 条的「直接写的四个工具对引擎关掉」本来就是对**所有**引擎跑的（同一个判断 `serving_engine()`），周回顾的提示词本来就禁止写。代价：无。⇒ 和 R1 一起做（不另加改动）。

**R3 · 网页靠标签页标题冒充 📖**
- 机会：要用户从一个故意起了「官方」标题的网页上捕东西。后果：收件的 AI 把那一块当事实、不反驳（表头写了「只在同样新的时候赢，后来的块说它变了就摆给用户」，有一层缓冲）。不是 §8 一类。
- 最小改法（候选，要 Ocean 定）：
  - 甲：表头 📖 那一节加一句「来源是网页标题的，标题是网页自己写的，不凭标题就当成机构来源」。代价：改表头（TS 和 Rust 两份逐字一样 + golden 要重生成）—— 任务书 §5「要动 pack 正文 / 表头先停下来问」。
  - 乙：捕捉时在浏览器来源前面加「浏览器名 · 」（例如 `Chrome · 标题`）。好处：「是网页」这件事由 Spool 定，网页改不了。代价：以后捕的块来源格式变了（旧块不变）；pack 里的样子跟着变，同样要动 golden。
  - 丙：不改，发版说明 / 帮助里也不提。
  - 推荐：放到发版二之后（`DISCOVERED-20261110-1`），P16 不碰表头。

**R4 · 剪贴板 HTML 里藏起来的字**
- 转换时没跳过 `hidden` 属性、`display:none` / `visibility:hidden` 的元素；只查「转出来的字比纯文字少太多」，不查「多太多」。浏览器复制时会不会把藏起来的元素放进剪贴板 HTML，**没实测**。（字号为 0、白字白底这类在 P14 之前就会跟着纯文字进来，捕捉这一层本来就挡不住，只能靠围栏。）
