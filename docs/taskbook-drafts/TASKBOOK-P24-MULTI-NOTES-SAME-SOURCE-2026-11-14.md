## 1. 要做的

### P24-1 · 先出一页设计，给 Ocean 选

把「怎么认出是同一份材料」「怎么在库里连起来」「项目里怎么显示」「打包里怎么写」四件事各列两三个做法，写清好处 / 代价。至少要比这几种（都只是候选）：

- 甲：新加一列，把同一份材料的几处连到一起（只加列、不重建表；库结构加一版，同抬 `mcp.rs` 的 `EXPECTED_SCHEMA_VERSION`）。
- 乙：借用现有的 `ref_block_id`，第二处指向第一处。代价：这一列现在的意思是「引用」，混进来以后读的人分不清。
- 丙：库不改，只在显示和打包时按来源标签和时间远近合在一起。代价：靠猜，标签一样的两份不同材料会被合错。

还要说清：怎么进入「再批一处」（捕捉卡上一个按钮？同一来源几分钟内再捕自动归一组？）——双击 ⌥ 直达批注框这条铁律不能破（记忆 `capture-note-first`）。

还要出两三个样子（11-18 加）：捕捉卡上怎么显示存到哪个项目、存错了怎么一步改。顺带看一眼：AI 写进来的更正也是挂在原文某一句上的批注（P16-8 在时间线上把它收成一行），两种批注的样子尽量一致；不给 AI 写回加功能（§3 照旧）。

### P24-2 · 照 Ocean 选的做

- Mac 和 Windows 都要能用。
- 捕捉卡上看得到这一条存到哪个项目，存错了一步改对；不破「双击 ⌥ 直达批注框」（11-18 加，第 383 条）。
- 打包（用户自己复制的那份）里看得出这几处属于同一份材料；MCP 那边的读法要不要跟着变，单独问（§4 第 2 问）。
- 改库结构：先在真库**副本**上跑真迁移，按记忆 `spool-db-wipe-incident` 的两条验证法验；不起 debug 版 GUI 连真库目录。

- **验收**（`DISCOVERED-20261113-2` 的验收标准）：对同一个来源连着存三处、各写一句，在项目里和打包结果里看得出它们来自同一份材料。另外：vitest、`cargo test --lib`、`tsc -b`、i18n 检查都过；单独存的一条，样子和现在一样；故意存到别的项目，在捕捉卡上一步改对（`DISCOVERED-20261117-3`）。
