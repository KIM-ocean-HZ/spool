## 1. 要做的

### P29-1 · 先出一页设计，给 Ocean 选

- 入口放哪；交出去的是什么（就是打包那份，还是可以只选几条）；用哪条路、哪个模型（没连 AI 时显示什么）。
- 答案怎么落：直接成为一条记录，还是先进待审（§4 第 1 问）；署名写什么（用 `src/lib/engine/ranBy.ts` 那种名字，不露模型 ID）。
- 已完成、已归档、私密的项目能不能问（§4 第 2 问）。
- 一次要多久、能不能停；停下时提示说什么（本机 CLI 那条不说「可能照样算钱」，见 `DISCOVERED-20261112-25`）。
- 答案的写法（11-18 加，第 381 条，软提醒）：结论先说、用用户的话；尽量不超过约 800 字，超了照样存下、不截断（给 AI 的提示里写明细节放进附件）；写了更正就顺手把项目摘要刷新成一句（约 150 字以内，同样只提醒）。同一条规矩也给 MCP 写回用（HANDOFF §5.0 第 10a 件）。数字下发时可再调。

### P29-2 · 照 Ocean 选的做

- Mac 和 Windows 都做（Windows 只有 API 那条路）。
- 命令都是 async，不冻界面。
- 不加 MCP 工具；如果最后要加，按 HANDOFF §4 那几条（annotations、两段路由文字、引擎该不该拿到）。

- **验收**（`DISCOVERED-20261113-4` 的验收标准）：点一下，把项目连同批注交给已连接的 AI，答案作为一条署名记录出现；不出现多轮对话的界面。另外：没连 AI 时入口说清楚怎么连；停下能停；界面上没有模型 ID、没有花费估算；vitest、`cargo test --lib`、`tsc -b`、i18n 都过。

## 2. 收尾

- 大白话；少用 emoji，一屏最多一个 ⚠️；界面上不出现只有开发者用得上的东西。
- 真跑用演示版或库副本；API key 只在对话里当环境变量给，不写进任何文件、提交或记忆；花钱先定上限。
- 提交只带自己改的文件（不用 `git stash`，提交前看 `git diff --stat`）；提交说明不加任何署名、不写执行用的工具名；每次提交后跑 `CLAUDE.md` §5 那条自查。
- 隐私说明、官网讲 AI 功能的地方要加这一项（规划 `04` 6.6 第 2 条的代价）。
- 做完按 HANDOFF 附录 H 第 4 条收尾。

## 3. 不做

- 不做聊天窗口、不做多轮对话、不做「接着问」。
- 不在手机上做（iPhone 第一版不做「问一次」）。
- 不加新的出网方式，不碰主进程。
- 不做 Windows 的本机 CLI 那条路。

## 4. 开工前要 Ocean 定的

1. **答案落成记录，还是先进待审**：
   - 甲：直接成为一条署名记录。好处：用户自己点的，问完就能看到。代价：和「AI 的写入只排队进待审」那条规矩要分开说清——这是用户自己发起、自己等着的答案。
   - 乙：先进待审，点了才进项目。好处：和现在所有 AI 写入一个规矩。代价：问一句要多点一下。
2. **已完成、私密的项目能不能问**：已完成的项目原来不许被 AI 批量处理；这是用户自己点的一次，算不算。
3. **一次最多交多少**：项目很大时截不截、怎么告诉用户。

## 5. 什么时候停下来问

- 凡是碰到下面这些，先问 Ocean，不直接做：改产品红线、推送、发版、换装、**花钱**（真跑 API）、对外发布内容、往 Spool 正式库里写。
- 要加 MCP 工具、改引擎的范围：先问。
- 要碰主进程出网：停。

## 6. 验收单（给 Ocean，换装之后）

1. 打开一个项目，点「问一次」，问一句。
2. 等答案：出现在项目里，署名是哪个 AI，没有模型编号。
3. 界面上没有聊天框，也不能接着问。
4. 断开 AI 再点一次：说清楚怎么连。
