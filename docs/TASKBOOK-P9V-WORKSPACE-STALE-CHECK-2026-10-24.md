### P9V-1 · 工作区那一份提示词 + 逐字闸 + 两条路（Rust）

- 新提示词 `STALE_WS_SYSTEM`（整段字面量，中文，和 `STALE_SYSTEM` 同一条写法纪律）：材料里每个项目前面一行 `==== P1 · 〈项目名〉 ====`，条目写成 `P2#3`；回答是一个 JSON 对象 `{"blocks":[…],"projects":[…]}`：
  - `blocks` 每项：`stale` / `by`（`P2#3` 这种）、`why`、`quote_stale`、`quote_new` —— 新旧可以同项目也可以跨项目；
  - `projects` 每项：`project`（`P3`）、`by`（证据那一条，`P1#4`，可以是别的项目、也可以是它自己）、`why`、`quote_old`（这个项目里某一条的原文）、`quote_new`（`by` 那一条里说明它结束 / 放弃 / 被接手的原文）。
- 闸：同一个 `locate`，每个项目的 pack 各自拆块（`blocks_of`）。`quote_old` 在那个项目的任意一块里逐字出现就算。对不上、编号不存在、指到自己的，整条丢掉、连原话带回来（和现在一样摆给他看）。
- 两个命令：`stale_scan_ws_via_cli`、`stale_scan_ws_via_api`，进来的是「几个项目各自的 pack + 名字」，出去的是过了闸的块级、项目级两批 + 丢掉的那批。共用压缩那把「正在跑」的锁。
- **验收**：cargo 单元测试 —— 提示词的样子（材料里有分隔行、规则里有 `P2#3`）、跨项目一对放行、撞号（`P1#3` 和 `P2#3` 不混）、项目级放行 / 丢掉、回答是数组或带代码块也能读、CLI 那条照旧不给任何工具（`ask_cli` 原有测试）。

### P9V-2 · 页签里查整个工作区（前端）

- 过期检测页签顶上一个二选一：**查整个〈Flux〉（4 个项目）| 只查这个项目**，默认前者。工作区里能查的项目不到两个（比如只有一个项目的子工作区）就不出这个选择，照旧只查这个项目。
- 工作区那一次的材料：这个项目所在的工作区 + 它下面的子工作区里，**没完成、不私密、至少有一块**的项目，每个一份 pack（和打包对话框同一个组装函数，⚠️ 不带每份开头那段「怎么读」—— 23 个项目就会重复 23 遍）。跳过的私密项目写明几个。
- 上限（**两条路各一个，我定的**）：本机 CLI **20 万字**、API **12 万字**。超了不发，页里写「这个工作区一共约 X 万字，超过一次能发的 Y 万字。可以先只查这个项目，或者把已经做完的项目标完成。」⇒ 按上面那张表：API 只有「升学（含学校）」发不出去；CLI 全都发得出去。
- 结果页两段：**被取代的旧块**（卡片和现在一样，三个按钮；跨项目时写成「〈midi-GPT〉#2 → 〈Flux〉#21」）+ **可能已经结束的项目**（「〈X〉看起来已经结束了 —— 理由；它自己的原话「…」；〈Y〉#4 里「…」」，两个按钮 **标完成**（打开和项目顶上「完成」同一个面板）/ **不动**）。
- 跨项目的「更正一处 / 整条取代」写的字段和现在一样（关系记在块上，不限项目）。
- **验收**：vitest —— 哪些项目进材料（完成 / 私密 / 空的不进、子工作区进）、上限、`P` 编号对回块、跨项目两道 T2 闸照旧拦、项目级「标完成」之后卡片显示已完成。
