# 产品任务书 P9V —— 过期检测查整个工作区；可以每月自动查一次

> **状态：ACTIVE**（2026-10-24 下发，同一窗执行；回执见 §7）。
>
> **唯一交付：** §3 的六步按顺序做完、每步一笔提交，§7 写回执；换装 → Ocean 验收 → 和 P9U 一起发 **v0.7.3（Mac）**（第 193 条，推送前问）。
>
> **来历：** Ocean 10-24 晚（§9.2 第 192 条）：「对于过期检测，我想在下一窗口做一个新功能，对于整个文件夹内部进行过期检测，和对于选定项目进行过期检测，因为我发现比如 flux 工作区有很多小项目，有一些早就过期了，可是在项目内部是没有过期的，如果把整个工作区放在一起检测才能查出来。」（「文件夹」= 工作区。）接在 P9U 后面，P9U 还在等他验收。
>
> **授权来源（HANDOFF §9.2 第 196 – 202 条，10-24 两轮问答）：**
> - 第 196 条：「过期」= **两种都要**：块级（别的项目里的新块整条取代了这个项目的旧块）+ 项目级（整个项目已经过时，建议标完成）。
> - 第 197 条：手动查和自动查的结果都落在**过期检测页签那一页**，不进待审；跟进照旧在待审。另：开了「每周自动查」的项目要在右栏看得出来。
> - 第 198 条：本机 CLI 和 API 都能**定期**过期检测，比跟进间隔长 ⇒ **每月一次**（30 天）。
> - 第 199 条：已完成 / 归档的项目**不参与**（不发、不提议）。
> - 第 200 条：入口**只在现在的过期检测页签**，不做左栏多选；范围 = **这个项目所在的工作区**（连它下面的子工作区）；页签上保留「只查这个项目」，**默认查整个工作区**。
> - 第 201 条：一次装不下 ⇒ **整个发，超过上限就不发**，告诉他少查一点。
> - 第 202 条：结果**存盘**，关掉 Spool 也在（手动、自动都存）。
>
> **边界：**
> - 不改库结构（v35 不动）。结果和自动开关存在自己的一个文件 `stale.json` 里（和 `drafts.json` 同一种做法），⛔ 不进 spool.db、不进 settings.json。
> - 不加 MCP 工具、不动引擎的 MCP 白名单（`ENGINE_EXCLUDED_TOOLS`）：自动过期检测是 Spool 自己发**一次**请求、不给任何工具，结果只等他点。
> - 私密项目、已完成的项目一个字都不发。
> - ⛔ 跑之前**不显示预计花多少钱**（D0 红线；上一轮问答时我说过「跑之前照旧显示大概多少钱」，那句是错的，这里更正）。跑之前只说要发几个项目、多少字；跑完照旧显示真实花费。
> - 「只查这个项目」那份提示词（`STALE_SYSTEM`）一个字不改 —— 它是实测过 60 次的那一版。
> - CLI 失败**不**自动改走 API。Windows 上本机 CLI 照旧关着。

## 2. 起点（10-24 对着 `65402bb` 查的）

- 过期检测一次只发**一个项目**的 pack（`compressStore.runStaleScan` → `stale_scan_via_cli` / `stale_scan_via_api`），提示词 `mcp.rs::STALE_SYSTEM`，回来的每一条过 `api_engine.rs::gate_proposals`：两句引文要逐字出现在那两块里，对不上整条丢掉（丢掉的照样摆给他看）。
- 块号 `#N` 每个项目自己数（`idx_blocks_thread_seq`）⇒ 几个项目放一起会撞号。
- 结果只在内存里（`StaleSession`），关掉 Spool 就没了。三个按钮：更正一处（`setBlockSupersession(…, 'corrects')`）/ 整条取代（`replaceBlock`）/ 不动。
- 库里一块本来就可以指着别的项目的块（真库里跨项目引用 69 条；跨项目的更正 / 取代 0 条，但字段和渲染都不限项目）。
- 「归档」不单独存：一个工作区（连子工作区）里的项目全标完成，它就进归档（`lib/workspaces/archive.ts`）。⇒「建议归档」= 建议把项目标完成。标完成走 `CompleteThreadPanel`（`setCompleting`）。
- 每周自动跟进：每个项目一个开关，存在 `threads.follow_up_state` 的 `auto`；`useAutoFollowUp` 每 10 分钟看一次，只在 Spool 开着时跑，开 app 那一刻不跑，失败也记时间。右栏只在「上次查过」那一行后面加一个灰色的「 · 每周自动查」—— 开着但还没查过的项目什么都不显示，这就是「有无自动分不出来」。

## 3. 六步

### P9V-0 · 任务书 + HANDOFF（这一笔）

### P9V-1 · 工作区那一份提示词 + 逐字闸 + 两条路（Rust）

- 新提示词 `STALE_WS_SYSTEM`（整段字面量，中文，和 `STALE_SYSTEM` 同一条写法纪律）：材料里每个项目前面一行 `==== P1 · 〈项目名〉 ====`，条目写成 `P2#3`；回答是一个 JSON 对象 `{"blocks":[…],"projects":[…]}`：
  - `blocks` 每项：`stale` / `by`（`P2#3` 这种）、`why`、`quote_stale`、`quote_new` —— 新旧可以同项目也可以跨项目；
  - `projects` 每项：`project`（`P3`）、`by`（证据那一条，`P1#4`，可以是别的项目、也可以是它自己）、`why`、`quote_old`（这个项目里某一条的原文）、`quote_new`（`by` 那一条里说明它结束 / 放弃 / 被接手的原文）。
- 闸：同一个 `locate`，每个项目的 pack 各自拆块（`blocks_of`）。`quote_old` 在那个项目的任意一块里逐字出现就算。对不上、编号不存在、指到自己的，整条丢掉、连原话带回来（和现在一样摆给他看）。
- 两个命令：`stale_scan_ws_via_cli`、`stale_scan_ws_via_api`，进来的是「几个项目各自的 pack + 名字」，出去的是过了闸的块级、项目级两批 + 丢掉的那批。共用压缩那把「正在跑」的锁。
- **验收**：cargo 单元测试 —— 提示词的样子（材料里有分隔行、规则里有 `P2#3`）、跨项目一对放行、撞号（`P1#3` 和 `P2#3` 不混）、项目级放行 / 丢掉、回答是数组或带代码块也能读、CLI 那条照旧不给任何工具（`ask_cli` 原有测试）。

### P9V-2 · 页签里查整个工作区（前端）

- 过期检测页签顶上一个二选一：**查整个〈Flux〉（4 个项目）| 只查这个项目**，默认前者。工作区里能查的项目不到两个（比如只有一个项目的子工作区）就不出这个选择，照旧只查这个项目。
- 工作区那一次的材料：这个项目所在的工作区 + 它下面的子工作区里，**没完成、不私密、至少有一块**的项目，每个一份 pack（和打包对话框同一个组装函数，⚠️ 不带每份开头那段「怎么读」—— 23 个项目就会重复 23 遍）。跳过的私密项目写明几个。
- 上限（**两条路各一个，我定的**）：本机 CLI **20 万字**、API **12 万字**。超了不发，页里写「这个工作区一共约 X 万字，超过一次能发的 Y 万字。可以先只查这个项目，或者把已经做完的项目标完成。」⇒ 按上面那张表：API 只有「升学（含学校）」发不出去；CLI 全都发得出去。
- 结果页两段：**被取代的旧块**（卡片和现在一样，三个按钮；跨项目时写成「〈midi-GPT〉#2 → 〈Flux〉#21」）+ **可能已经结束的项目**（「〈X〉看起来已经结束了 —— 理由；它自己的原话「…」；〈Y〉#4 里「…」」，两个按钮 **标完成**（打开和项目顶上「完成」同一个面板）/ **不动**）。
- 跨项目的「更正一处 / 整条取代」写的字段和现在一样（关系记在块上，不限项目）。
- **验收**：vitest —— 哪些项目进材料（完成 / 私密 / 空的不进、子工作区进）、上限、`P` 编号对回块、跨项目两道 T2 闸照旧拦、项目级「标完成」之后卡片显示已完成。

### P9V-3 · 结果存盘（第 202 条）

- `stale.json`（`@tauri-apps/plugin-store`，和 `drafts.json` 同目录）：每个「范围」一份最新结果（只查这个项目 = 按项目存；整个工作区 = 按工作区存），存的是块的 id，不是整份 pack。打开 Spool 读回来；下一次查同一个范围就换掉旧的。读坏了当没有。
- 「清除所有数据」一起清。页签上的数（「过期检测（3）」）照这一页现在显示的那份结果算。
- **验收**：vitest —— 存进去读得回、形状不对的丢掉、清除。

### P9V-4 · 每月自动查一次（第 198 条）

- 页签里选「查整个工作区」时，底下一个开关「**每月自动查一次〈Flux〉**」，管的是整个工作区，**默认关**，和「用 本机 CLI / API」那个选择走同一条路。开关和上次时间也存在 `stale.json`。
- 定时和自动跟进一样：Spool 开着时每 10 分钟看一次，开 app 那一刻不跑；离上次满 30 天才跑；一次只跑一个工作区；有别的在跑（压缩、过期检测、引擎排着队）就等下一次；「显示 AI 功能」关着、两条路都没连上就不跑；工作区里能查的项目不到两个就跳过。超上限、失败、停下都记上时间（不会每 10 分钟重试花他的额度）。
- 结果落在同一页，标一句「每月自动查的（10-24）」。
- **验收**：vitest —— 到期判断（没满 30 天不跑、挑最久没查的、关着不跑）、超上限也记时间。

## 4. 什么时候停下来问

- 真跑用 Ocean 的 Codex 额度、或要 API key 之前。
- 新提示词在副本上真跑出来明显不对（比如把还在做的项目判成结束了）—— 先把原话给他看，再决定改提示词还是改闸。
- 要改库、改 MCP 工具、或范围超出上面六步。

## 5. 不做的

- 左栏多选几个项目一起查（第 200 条舍掉）。
- 工作区右键菜单里的入口（第 200 条：只在页签里）。
- 自动查的结果弹通知 / 进待审（第 197 条：只落在页签那一页，页签上有数）。
