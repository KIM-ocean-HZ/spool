## 2. H2 —— AI 通过 MCP 写回之后，正开着的项目页不刷新

### 2.1 事实（对着代码查的）

- **服务端什么时候提交**：`add_block` 在一个事务里写完、`tx.commit()`（`mcp.rs` 5861），**之后**才拼回执。回执到手 = 已经提交。
- **有没有发通知**：没有。`--mcp` 进程和 GUI 之间只共享 SQLite 文件，没有任何消息通道（P4-2 当时明确定了「不在 Rust / MCP 那边加东西」）。
- **前端什么时候读**：两条路，都在 `stores/outsideWrites.ts`：
  1. 窗口拿到焦点（`App.tsx` 的 `focus` 监听）⇒ 重读；
  2. 每 3 秒查一次「记号」（`librarySignature`：几张表的行数 + 最新时间，一条查询），变了才重读 ——
     ⚠️ **但 `document.visibilityState !== 'visible'` 时直接跳过**（P4-2 任务书第 3 条「看不见就停」）。
- **重读读什么**：项目列表 → 当前项目的块（`blocksStore.load`，整份替换，按块 id 渲染）→ 待审数 → 左栏绿点。页面直接从 `byThread[当前项目]` 画，重读了就看得见。

新块每次都只出现一次（重读是整份替换）。短命 MCP（每次新起进程）和常驻 MCP（一个进程写两次）没有区别 —— 服务端每次都已提交，差别只在 GUI 有没有去读。

### 2.3 根因

**窗口看不见的时候，GUI 不去读；而它看不见的这段时间里，没有任何东西会让它去读。** 人回来时有两条路兜底（拿到焦点马上读；或者窗口重新露出来、下一次查记号时读，最多 3 秒），所以人一般只会碰到「切回来要等一两秒」。

T06 是另一种：Codex 用电脑操作（读的是辅助功能树 —— 证据文件就是这棵树的文本）去「看」Spool，**这既不让窗口变成看得见，也不给它焦点**，两条路都不触发。
证据：18:32:08 回执到手，18:32:16 读到的界面里 CV 仍是 4 块，而且左栏 CV 那一行**没有**绿点 —— 要是重读过，新块不在屏幕上、绿点一定会亮。之后用搜索打开 CV，走的是「打开项目」那一次 `load`，所以看见了。
（「Codex 的电脑操作不给焦点」是从证据推断的，没在 Codex 那边单独测。）

⇒ 不需要改库结构，也不需要服务端发通知。

## 3. H3 —— 附件到底有没有交给 AI

### 3.1 现在有几种状态（对着代码查的，库里已经分得出来，不用改结构）

| 状态 | 库里怎么分 | 用户在右栏看到的 |
|---|---|---|
| 文字在 pack 里 | 有 `extracted_text`，「打包可读」开（MCP 那份还要「AI 可读」开） | 「打包可读」勾着 |
| 文字在 pack 里、但被截断 | 同上，正文超过 8000 字（`EXTRACT_CHAR_CAP`） | 同上 |
| 能读、但没放进 pack | 有 `extracted_text`，「AI 可读」开、「打包可读」关 | 只勾「AI 可读」 |
| 没许可 | 有 `extracted_text`，「AI 可读」关 | 「AI 可读」没勾 |
| 读不出文字 | `extraction_kind = 'failed'` | — |
| Spool 没有它的文字 | 没提取过（`extracted_at` 为空，如 .key、文件夹、关了自动提取） | — |
| 原件跟着走 | 只在「导出文件夹」里：勾上的文件拷进 `files/`，名字是链接 | 导出清单里勾着 |

### 3.2 复现（同一个七文件样本，三条通道）

样本：〈P14 附件矩阵〉项目，A1 课程笔记.pdf（打包可读 + AI 可读，1200 字）· A2 简历-文书版.docx（只 AI 可读，3600 字，= T02 的情形）· A3 推荐信草稿.docx（只打包可读，2000 字）· A4 成绩单.pdf（都不勾，900 字）· A5 扫描件.pdf（读不出）· A6 演示.key（没提取过）· A7 长报告.pdf（都勾，12000 字）。
每个文件的正文里放了不同的记号字，用来查谁的字漏到了哪里。

**MCP（测试版的 `--mcp`）：**

```
get_pack 的文件那几行：
- 课程笔记.pdf (pdf) · on project                     ← 正文在
- 简历-文书版.docx  [extracted: yes, not inlined] · on #1   ← 能读，但和下面两个锁着的长得一样
- 推荐信草稿.docx  [extracted: yes, not inlined] · on project
- 成绩单.pdf  [extracted: yes, not inlined] · on project
- 扫描件.pdf · on project                              ← 读不出
- 演示.key · on project                                ← 没提取过，和上一行一样
- 长报告.pdf (pdf) · on project                        ← 正文后面是 [... truncated, 4000 more chars not shown ...]
pack 后面「没开给你的文件」只列了推荐信草稿、成绩单（对）。
```

- 表头说 `[extracted: yes, not inlined]`「means the text exists and you may ask the user for it」—— 对简历这一个是错的：它**已经能读**，`get_blocks(include_extracted_text=true)` 当场就回 3600 字，pack 里没有任何一句指过去。这就是 T02 / T03。
- 读不出（A5）和没提取过（A6）一模一样。
- A7 说「4000 more chars not shown」，没说去哪儿读剩下的（`get_blocks` 能给全文 12000 字）。
- `get_blocks` 里 A3 是 `inlined_in_pack: true`、`ai_readable: false` —— 而 `get_pack` 并没有放它的字。这个字段说的是「用户自己复制的那份里放了」（08-19 有测试特意钉住这个意思），可 AI 读起来像「你拿到的 pack 里有」。A5 是 `ai_readable: true`、没有字，也没有一句为什么。
- 锁着的 A3 / A4 的记号字在 `get_pack`、两种 `get_blocks` 里一次都没出现（权限是对的，这次不动）。

**手工复制（PackDialog 的「复制」= `assemble()`）：** A1、A3、A7 的字在（A3 是用户自己勾的，复制的是用户自己，对）；A2、A4 是 `not inlined`；A5、A6 分不开；A7 截断同上。
对话框里**没有任何地方告诉用户**「有 4 个文件的字没跟着复制出去」—— 用户贴给别的 AI，以为全带了。

**导出文件夹（P8，默认全勾）：** 七个原件都拷进了 `files/`，名字都是链接；但 A2、A4 那一行仍然写 `[extracted: yes, not inlined]`，表头仍然叫对方「去问用户」—— 原件明明就在旁边。

### 3.3 根因

三条通道共用一套文件行和一段表头，而那段表头只写了一种「没放进来」，还配了一句只对一部分情况成立的「去问用户」。库里分得清的七种状态，到了 AI 手里只剩三种样子。MCP 那边给「锁着的」单独加了一段出路（`pack_locked_files`），「能读但没放进来」「截断」「读不出」没有。
