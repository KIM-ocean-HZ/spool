用户希望突出深入研究 AI memory 的方向，可以在 P15 的概念画面加 **Built around how AI reads project context.**，用资料 → 用户判断 → 新结论 → 更正关系的真实细节支撑。不要把尚未完成的研究写成“已证明最可靠”或“永远不会忘”。无需削弱语气，重点是把强度放在用户可看见的体验。

## 5. 比较卡片怎么进入成片

主版本 P03 采用两张概括痛点卡，并在视频简介给研究来源。要使用真实用户反馈时，从 [04](04-research-and-claims.md) 选 F1 / F2，改成清晰标记的“用户报告 · 转述”，保留平台、年月及来源编号。文案与画面不伪装为真实聊天或官方承认。

可用文字：

- “A fresh thread couldn't access the thread tools I expected.” — User report, Codex Desktop, Oct 2026, paraphrased.
- “My older project still needed manual file uploads.” — User report, Claude Desktop, Sep 2026, paraphrased.

这两句为转述，不加英文引号作为逐字引文；制作时以上引号只表示文案边界。镜内仅用一行短文，完整限定放视频简介。F2 的 issue 被标记为不属于 Claude Code，因此标 **Claude Desktop**，也不能当成厂商确认缺陷。发行前复查状态；若已经解决，回到概括痛点卡即可，不影响主片。

超级 Agent 不专门给一整段批判。P13 通过“执行越来越多时，我的思路是否仍可追溯”表达选择，约 8 秒完成。OpenClaw 名称可放视频简介的延伸比较，主片不需要用其 Logo 制造阵营对立。

## 6. 画面与声音制作规格

- 主交付：3840×2160，30fps，16:9；录屏源建议 60fps，剪辑时间线 30fps。保留无字幕干净版、英文字幕版与中文字幕版。
- 真实 UI 占满或占画面 70% 以上时，正文在 1080p 播放下仍能辨认；需要读的段落裁到 1–3 行，不把整张 3600px 图缩得无法看字。
- 标题使用现有品牌衬线感，正文使用清楚的无衬线字；米白底、深墨文字、琥珀强调。新文字放剪辑层，别生成到图片里。
- 每个画面只表达一个主动作。字幕至多两行，每行尽量不超过约 42 个英文字元；手机竖版重新排，不直接裁掉侧栏和浮窗。
- 概念镜头约 24–35mm 的温和透视、轻推镜、柔和阴影；真实 UI 画面避免大角度倾斜和过量模糊。
- 音乐：温暖、轻盈、有前进感的电子 / 轻打击乐，约 95–110 BPM；不要用悲惨焦虑配乐羞辱观众。人声段音乐降低；网络等待不能靠过密音效伪装即时。
- 混音目标：成片约 −14 LUFS integrated，true peak 不高于 −1 dBTP；以耳听复核人声清晰度。
- 所有引擎等待用剪辑缩短，首次注明 Waiting time shortened。用“Several days later”表现积累，不能让观众误以为一次点击自动完成整个项目。

## 8. 成片自检

找一个没用过 Spool 的人看一次，不先讲产品。如果他能回答“记录到哪个项目”“AI 怎么用它”“换 AI 会怎样”“下一步怎样开始”，主片解释成立。若他只记住漂亮的纸张渲染，缩减 P18，给 P06 和 P12 各多 2–3 秒。

最重要的三条证据：捕捉时原页面不跳走；用户自己的判断在 AI 回答里生效；第二个 AI 读到第一个 AI 新写回的结论。三条都需要真实素材。
