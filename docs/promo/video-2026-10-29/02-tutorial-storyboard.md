## 1. 教程承诺与录制方式

开场就说清：前五分钟可以学会捕捉、文件和 Pack，用平时的 AI 得到第一份有针对性的建议。后半段按需学习 MCP、自动跟进、压缩、过期检测、代码仓库和周回顾。观众可以先停在 Pack，不需要为了开始就把所有连接都配置好。

真人只在开场、解释“我的判断”和结束时全屏；操作时录屏占满。涉及决定和权限时可右下角小窗露面，避免遮住右栏和待审按钮。讲解不边移动鼠标边介绍另一个区域；说到哪里就先把指针停在哪里。

以下各段“讲稿”可直接口播；操作与成功画面不读出来。第一遍慢速演示后，重复动作可以加速。录制总素材可能 35–50 分钟，剪掉等待与重录后成为约 17 分钟教程。

## 3. 逐段口播与操作

### T01 · 00:00–00:35 · 先展示结果

**操作 / 画面**：真人 5 秒 → Portfolio site 时间线 → 一个 AI 根据用户批注给建议 → 完成的作品集本地预览。最后用真实 Welcome to Spool! 捕捉浮窗进入教程。

**讲稿**：

> 这个作品集项目里，有我浏览时抓下来的资料、文件、我自己的想法，还有和不同 AI 讨论后确定的决定。今天我会从创建项目开始，把这一整条流程做一遍，最后完成并归档。
>
> 前五分钟你就能用起来，后面再讲更省事的 AI 连接和维护功能。我们先做一件真实的事：把三篇项目案例整理到可以提交。

**剪辑**：标题卡 Build a portfolio. Keep the context.；只预告结果，不把后面的教程再快放一遍。

### T02 · 00:35–01:25 · 创建项目

**操作**：在干净的拍摄状态创建工作区 Work，再创建 Portfolio site；若工作区已经在演示库里，只演示创建项目。写一句目标，设拍摄时选定的截止日期，把它设为当前捕捉目标。教程同名项目从空白状态录起，稍后的积累状态用同一个拍摄副本继续。

**讲稿**：

> 工作区是我放相关项目的地方，比如工作、学习和生活。项目则是一件我想推进的事。这里叫 Portfolio site。
>
> 我先写一句目标：三篇项目案例，整理到可以提交。再留一条自己的限制：最多三个项目，保留音乐项目，暂时不做博客。这些是我的取舍，后面让 AI 帮忙时也应该尊重它们。
>
> 把它设为当前捕捉位置以后，在别的软件里抓到的东西就会进这里，不用每次再挑一次文件夹。

**成功画面**：项目标题、目标、用户限制、Capturing 指示同屏。停 2 秒。

### T03 · 01:25–02:25 · 连接文件夹与添加文件

**操作**：点击工作区名称进入工作区页 → Connect a folder… → 选拍摄用 portfolio-site 文件夹 → 在四步向导选择 README.md / PLAN.md → 保持 SPOOL.md 本机可见的默认选择 → 选择是否向现有指令文件添加指向它的说明 → 设 Portfolio site 为 Main project。回项目，向 Project files 添加 case-study-draft.md 和演示图片。

**讲稿**：

> 如果这件事已经有本机文件夹，可以把工作区连过去。注意，连接属于工作区，不是给一个项目悄悄加上整个磁盘。同一工作区和子工作区里符合条件的未完成项目会共享这个连接；Main project 是 AI 默认写回的项目。
>
> 我选择 PLAN 和 README 作为说明当前进度的文件。Spool 能提醒我这些文件变了；代码仓库怎样利用 SPOOL.md，后面再实际做。
>
> 连接文件夹和添加附件是两件事。这里的案例草稿是我要给这个项目参考的文件，所以把它放到 Project files。连接文件夹不等于所有文件已经全文导入，也不等于每个 AI 都能直接访问整个文件夹。

**成功画面**：文件夹卡显示状态文件；项目文件列表显示两份附件。四步向导标题各停留至少 1 秒，不能全部跳过只说“一键”。

### T04 · 02:25–03:20 · 捕捉文字

**操作**：回到演示来源页面，选中案例结构段落 → ⌘C → 双击 ⌥ → 真实捕捉卡显示目标与来源 → 按 Enter 完成。保留原页面滚动位置。第一次完整连续实录，再回项目看块。

**讲稿**：

> 我现在仍然在浏览资料。看到这段有用，复制，然后双击 Option。这张小卡出来时，内容已经到了当前项目；我不需要打开主窗口、找一页笔记，再重新排版。
>
> 看这里的项目名和来源。来源能帮我之后知道这句话从哪儿来；如果自动识别得不准，可以当场改。时间也会留下来。
>
> Windows 的动作是复制后双击 Ctrl。第一次在 Mac 上使用双击捕捉，需要完成输入监听的授权；想弹出后直接打批注，也要按界面提示完成辅助功能设置。

**成功画面**：原页面保持原位；回项目能看到新增块及来源。角标：macOS ⌘C → ⌥⌥ / Windows Ctrl+C → Ctrl×2。

**录制注意**：权限设置可用 6–8 秒补充插片说明，不在主流程里临时重启。完整配置后的第一次成功必须保留连续动作。

### T05 · 03:20–04:10 · 截图与批注

**操作**：Mac 使用 Control+Shift+Command+4 将框选截图送到剪贴板，再双击 ⌥。Windows 用 Win+Shift+S 截图入剪贴板，再双击 Ctrl。捕捉卡内输入 Keep the music project. It shows how I think.；保存，回时间线查看图片与批注。

**讲稿**：

> 图片也是一样。把截图放到剪贴板，再捕捉。我这里留的是作品集草稿里音乐项目的画面。
>
> 我会加一句：保留音乐项目，它能体现我的思考方式。这句话比“以后再看”有用，因为它说明这张图对当前项目到底意味着什么。
>
> 不需要把每条资料整理成漂亮长文。先留住它，再用自己的话说明为什么重要。需要认真理解的内容，仍然可以推导、练习和复习；Spool 帮我把这些思考接到正在做的事情上。

**成功画面**：图片、原始内容、用户批注同屏。强调“批注是用户写的”，与后面的 AI 标签形成视觉呼应。

### T06 · 04:10–05:00 · Pack 给常用 AI

**操作**：Pack → 检查项目内容 → Copy → 打开常用 AI 新对话 → 粘贴 Pack 和 D-P1 任务 → 真实回答提到最多三篇、保留音乐、暂不做博客。

**讲稿**：

> 现在已经可以和 AI 一起做事了。点 Pack，Spool 会把这个项目整理成能直接交给 AI 的上下文。复制后，粘贴到你平时用的聊天里，再说要做什么。
>
> 我问：根据这些资料，帮我安排今天最值得先做的三件事。这里要观察的不是它写得多长，而是有没有用上我自己的取舍。
>
> 这条路不需要 API key，也不需要 MCP。你照常使用自己的 AI 服务和额度。从这里开始，就已经能解决反复找资料、反复解释的问题。

**成功画面**：原话与 AI 回答中的对应限制各放大一次。若模型没遵守，保留纠正过程或换一遍合适任务实录，不能直接伪造回答。

### T07 · 05:00–06:10 · MCP：让 AI 自己读取

**操作**：Settings → MCP → 展示 MCP server 和 Allow AI writes 两个独立开关；连接一个真实拍摄客户端并重启客户端。用 D-P2 让它查项目；查看工具调用、来源和项目名。第二客户端可以提前连接，T09 再用。

**讲稿**：

> Pack 是我主动把项目交过去。MCP 则让支持连接的 AI 按需要自己来读，也能把新结论写回。所以普通使用从 Pack 开始就够了，想减少来回复制，再开这个连接。
>
> 这里有两道开关：允许读，和允许 AI 写。连接配置写好以后，要重启客户端，让它真的加载。界面显示写过配置，不代表对话已经读到了项目，所以我会实际问一次。
>
> Spool 的连接列表包括 Claude Desktop、Claude Code、Codex、Cursor、Visual Studio Code 和 Windsurf；其他兼容本地 stdio MCP 的客户端可以按自己的方式配置。这里的 Codex 也包括具备本地能力的桌面工作环境；普通远程 ChatGPT 对话不能直接连本机 stdio，仍然可以用刚才的 Pack。

**成功画面**：真正的项目读取调用与回答，不以“Connected”字样代替完整验证。

**拍摄环境特别说明**：演示版不覆盖日常 AI 客户端的生产配置。实际连接步骤在独立的拍摄配置 / 测试客户端里录，数据目录指向演示库；详见 03 §2。此段讲解的是正常用户流程。

### T08 · 06:10–07:00 · 写回结论与 Follow up

**操作**：使用 D-P3 保存这次推理得出的新决定：“先完成音乐案例，再精修另外两篇，不加第四个项目”；让 AI 提议一条跟进行。新结论通过 add_block 写入，跟进行在待审处由用户接受。另拍一张取代旧块的待审卡，解释区别。

**讲稿**：

> 这次讨论确定了一件新事：先完成音乐案例。我让 AI 把这个结论写回，而不是把整段对话再存一遍。
>
> 看新增块的来源，能知道是谁写的。AI 的结论不会冒充我当时的原话。普通追加结论可以直接出现；跟进行、批量提议和取代旧决定这些动作，则会在相应待审处等我确认。
>
> 跟进行用一句话说“还要盯什么”，比如作品集用到的图像方案有没有新的官方变化。它先是一个提议，我接受后才开始跟。

**成功画面**：AI 来源标签 + 一条真实新结论；跟进行从 proposed 变为可跟进的状态。别把所有 AI 写入都说成“每一条都需人工审批”。

### T09 · 07:00–07:55 · 第二个 AI 接力

**操作**：AI A 写入后切到 AI B 新对话。只输入 D-P4，不重新粘贴音乐决定；让它从 Spool 读取 Portfolio site，再问今天该先做什么。显示它找到的新结论与出处。

**讲稿**：

> 接下来我换一个 AI。我只说继续这个项目，没有把刚才的决定再讲一次。
>
> 它从同一个 Spool 项目读到刚才的新结论，也知道我为什么要保留音乐项目。这就是这里最重要的区别：项目资料和我的思考不需要只留在某一个聊天窗口里。
>
> 这不等于两个 AI 会自动互相聊天，也不是把所有聊天历史同步到一起。共享的是我选择留下、并且通过 Spool 交给它们的项目内容。

**成功画面**：AI B 正确说出 AI A 刚保存的新决定。没有这条，不用两排 Logo 替代证明。

### T10 · 07:55–09:05 · CLI 联网跟进

**操作**：Settings → AI engine → Local CLI 显示已检测到的可用工具。回跟进编辑器，看已接受的一条跟进行 → Search the web → With Local CLI。运行一次，剪掉等待；有更新时到待审读来源并接受，没有更新时保留无新消息状态。最后展示每周自动开关。

**讲稿**：

> 讨论可以用聊天客户端；维护项目也可以交给自己机器上的 AI 引擎。这里检测到我已经安装并登录的 CLI。它用的是我自己的账户和额度，不需要另外填 API key，也会消耗对应服务的使用量。
>
> 联网跟进只围绕我接受的这些问题查。查到值得留下的新内容，先给我看来源，再由我决定是否收下；没有新东西就保持安静。
>
> 这个开关可以每周自动查一次。它默认关着，要自己打开，Spool 开着时才会运行。CLI 里的 Claude Code 和 Codex 可以用来跟进；Gemini CLI 可以做另外的维护工作，但这条联网跟进不走它。

**成功画面**：当前路线、运行结果、待审结果或无更新状态、自动开关四个状态各拍一遍。讲到自动时只展示设置，不需要更改系统时间制造“已经运行一周”。

### T11 · 09:05–09:50 · API 路线

**操作**：设置页展示 Local CLI / API key 两个入口；API key 仅演示空输入框或已配置的掩码，不展示粘贴密钥。切回某动作的路线选择。使用有联网搜索能力的配置拍 Follow up，或在此段只拍设置，实际调用用 Weekly review。

**讲稿**：

> 如果更喜欢自己的 API，也可以选另一条路。每个动作旁边都能选择用本机 CLI 还是 API，前提是这条路线对这个动作可用。
>
> API key 和费用属于你自己的服务账户。周回顾、压缩和过期检测可以走兼容的文本模型接口；联网跟进还需要对应提供方支持网页搜索。没有搜索能力的接口不会因为填了 key 就突然能联网。
>
> 两条路都是可选的。想先用起来，前面的捕捉和 Pack 已经够了。

**成功画面**：两个入口和一个实际路线选择。教程不讲“免费、无限、不占额度”，也不把 API key 配置作为首启必要条件。

### T12 · 09:50–10:45 · 压缩与排队

**操作**：进入长项目演示状态 → Compress → 本地预检 → 选择合适档位及路线 → 运行 → 展示前后逐条对照，检查数字、日期和用户限制 → 明确保存。另录加入今晚队列和时间设置。

**讲稿**：

> 项目积累很久以后，可以把冗长内容压短。先看本地预检，有些项目没什么重复，压缩也省不了多少，就没必要跑。
>
> 真正运行后，我会看前后对照，尤其是数字、日期，还有“最多三个项目”这种不能丢的条件。这里保存的是我核对后的结果，不是 AI 一说压好了就悄悄替换。
>
> 多个项目可以放进夜间队列，到设定时间先生成结果，再回来核对。需要 Spool 运行；没有开着时不是关机后还在云端继续替你处理。

**成功画面**：一次真实对照与保存；队列配置另拍。不用旧截图里的百分比作为本片实测结果，字幕只写实际得到的数字。

### T13 · 10:45–11:45 · 过期检测

**操作**：同一项目已存在明确冲突：旧块“首页先放六个项目”，新块“最多三个”。Out-of-date check → 指定项目 / 工作区范围 → 运行 → 读新旧引文和理由 → 用户选 Replace in full 或 Leave alone。工作区层面展示每月自动检查开关。

**讲稿**：

> 内容变短和内容仍然适用是两件事。比如我早期想放六个项目，现在决定只留三个，旧前提就不应该继续和新决定平起平坐。
>
> 过期检测把可能被新内容替代的旧块找出来，让我看新旧依据，再决定是更正一处、整块取代，还是都留下。单纯“时间早”不是失效的理由。
>
> 也可以对整个工作区检查，按月自动生成结果。自动的是检查，改变历史仍然要我选择。过去的内容可以保留检索，新任务则按当前有效的信息继续。

**成功画面**：一对有明确前提变化的新旧块及用户决定；不能只录 Loading。若真实扫描没有命中，保留真实无结果，再用 MCP 取代提议讲解用户选择，明确区分两条来源。

### T14 · 11:45–13:10 · 仓库和 SPOOL.md

**操作**：回已连接的演示 portfolio-site 仓库。打开 SPOOL.md，只展示可读规则和项目对应关系；在 PLAN.md 修改一个实际方向。回工作区看到 changed。让仓库内 Agent 按 D-P6 读取当前状态、核对 Spool、写回新决定和未解问题，最后 mark_folder_synced 或用户确认 In sync now。画面显示回到同步状态。

**讲稿**：

> 如果你用代码仓库，SPOOL.md 的作用是告诉在这个文件夹里工作的 Agent：这个仓库对应哪些 Spool 项目，什么时候需要读，什么时候应该把重要决定写回来。
>
> 名字是大写的 SPOOL.md。连接时可以让现有 CLAUDE.md 或 AGENTS.md 指向它。它提供工作约定，不会让每个客户端无条件自动读懂，也不把文件夹的当前状态交给旧笔记决定。
>
> 我现在改了 PLAN：音乐案例先做，而且博客仍然推迟。Spool 提醒状态文件变了，这时自动跟进会先暂停，避免继续沿着旧计划查。
>

**成功画面**：SPOOL.md → PLAN changed → 写回变更 → In sync。不能先按 In sync now 再把未处理变化剪掉。片中不露原始项目 ID、个人路径或生产仓库。

### T15 · 13:10–14:20 · 周回顾

**操作**：Weekly review 页面 → 选择时间窗口和路线 → 用 Local CLI 跑一遍。剪到结果，逐项看项目、完成内容、卡点和建议；API 路线另录 5–8 秒“选择 API → 结果页”，不重复完整等待过程。

**讲稿**：

> 做了一周以后，我更想知道事情推进到了哪里，而不是再复习一遍所有笔记。周回顾会把这些项目里的进展、还没解决的事和下一步整理在一起。
>

>
> 我会先看它引用的依据，再决定是否接受建议。比如它发现音乐案例还差一段结果说明，这就是我今天能完成的一件具体工作。

### T16 · 14:20–15:10 · 采纳建议：两个录制版本

这段保留用户要求的“接受周回顾建议”，但取决于拍摄版本。**v0.7.4 tag 有周回顾卡片，没有 P10 的动作按钮。** 当前 main 有结构化周回顾及动作，不能只看 About 里的 0.7.4 字样来判断。

- 操作：点一条建议添加 Follow up / 改截止日期；显示生效；演示一次撤销。取代 / 更正建议点后进入待审，再由用户选择。
- 口播：

> 这个版本可以直接把回顾里的建议变成动作。比如添加跟进行、改截止日期，或者把已经做完的项目标完成。需要改变旧结论的建议会先进入待审。每一步仍由我决定，刚才的操作也可以撤销。

**B · 严格用 v0.7.4 tag 拍摄时，完整可用的版本**

两版均能接下段完成流程；制作时只保留一版。按用户要求优先保留完整功能讲解，但尚未具备按钮的构建就用 B，不阻塞整支教程。

## 4. 两个平台的拍法

| 动作 | macOS 主录 | Windows 插片 |
|---|---|---|
| 复制文字 | ⌘C | Ctrl+C |
| 双击捕捉 | 双击 ⌥ | 双击 Ctrl |
| 截图入剪贴板 | Control+Shift+Command+4 | Win+Shift+S，框选后确认剪贴板有图 |
| Pack 快捷键 | ⌘⇧P | Ctrl+Shift+P |
| 撤销 | ⌘Z | Ctrl+Z |
| 来源信息 | 已授权浏览器可有标签页标题 / 地址；以真实捕捉结果为准 | 主要记录来源应用，不把 Mac 的浏览器标题效果贴上去 |
| 首次权限 | 输入监听；辅助功能影响键盘进入批注等体验，浏览器信息还涉及 Automation | 按 Windows 实际表现录，不能插入 Mac 权限页 |

Windows 只需单独拍“文字捕捉、图片捕捉、Pack、右栏与周回顾”几个关键镜头；片中标 Windows 即可，不必每步都重复两次。

## 5. 需要交给剪辑者的边界

- 真实操作保留点击前、点击、成功后的关系；运行等待可以剪，首次标 Waiting time shortened。
- Pack 手动交接与 MCP 自动读取分两段讲清；Pack 不会让远程聊天直接写本机数据。
- 新增结论和改变旧结论分清；普通追加、跟进建议、取代提议的行为不同。
- 压缩、月度过期检查和每周跟进都展示自动运行的范围；不暗示用户无需审核，或应用退出后还有云服务代跑。
- `SPOOL.md` 是对齐约定；文件夹当前状态更权威，Agent 仍需读取并遵循。不能说“放一个文件以后任何 AI 永远自动对齐”。
- 试录时若超 18 分钟，先删重复等待、完整客户端列表的口播和第二条引擎的重复过程，保留第一条捕捉与跨 AI 接力的完整证据。
