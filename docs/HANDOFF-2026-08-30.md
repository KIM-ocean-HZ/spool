### 2.1 ✅ MCP supersede 提案被静默吞掉 —— 修了

Ocean 反映「AI 说有两条在 Spool 等我，界面上找不到」。⛔ **不是页签没刷新**：
`loadProposedStale` 用的是扫描那把尺子 `relationAlreadySettled`（问「这两块有没有关系」），
而两对块都已经带着 `corrects` ⇒ 两条提案被静默滤掉，页签根本不出现。

修法：新增第三道闸 `supersedeProposalSettled`（`lib/blocks/staleGuards.ts`），问的是
**「提案要的那件事做完没有」**：

| 库里 | 判定 |
|---|---|
| `corrects` | **显示**（旧块留着 ≠ 整条退掉，两个决定） |
| `supersedes` + 旧块已退役 | 隐藏（做完了） |
| `supersedes` + 旧块仍 live | **显示**（只做了一半 ⇒ 重试入口） |
| `cites` | 隐藏（用户自己连的线，T2 那条保护没动） |

⭐ 第三行是 Ocean 复核抓出来的：`setBlockSupersession` 的两条 SQL **中间没有事务**，
而且退役按钮是个纯开关（`BlockItem.tsx` → `setStale`，"the action is its own inverse"），
⇒ 半成品状态**日常路径就到得了**，那时旧块照样进 pack。
⛔ **扫描结果自己那条防重复规则一个字没改。**

**回执**：Ocean 08-29 夜里在界面上批了那两条，落地干净 —— `#23 supersedes #21`、
`#26 supersedes #23`，两个旧块退役，`corrected_quote` 按规矩清掉，提案表清零。

### 2.2 ✅ 「合并」→「更正一处」（Ocean 08-30 拍板）

### 2.3 ✅ 引用一块已退役的块 —— 三处渲染对齐（Ocean 选「乙 · 标出来 + 收掉预览」）

**问题**：退役的块自己离开 pack，但引用它的那一行照常打它的时间戳 + 开头 40 字，
和引用一块 live 的块**一模一样**。⇒ ① 读的人看不出被引的东西已作废；
② ⛔ 退役内容顺着引用行**漏回 pack**，而同一份 pack 里还写着「有 N 块已标记为不再有效、未显示」。

**改的三处**：`pack/templates.ts`（新常量 `REF_BLOCK_RETIRED`）、`pack/assemble.ts` +
两个 `refBlocks` 构造点（`forThread.ts`、`WorkspacePackHost.tsx`）、`mcp.rs`（常量 +
`RefBlock.stale` + **SQL 补 `b.stale_at`** + 同样分支）、`CitationLine.tsx`（feed 里加「已不作数」）。

⭐ **`stale` 省略读作「还有效」是故意的**：漏标一条只是少一句提示，反过来会把满屏 live 的
引用全说成作废 —— 那个错贵得多，有测试钉着。

⭐ **界面上没发明新词**：用的是退役块自己头上那行的说法「不作数了」（`BlockItem.tsx`）。

#### ⛔⛔ `supersedes` 是例外 —— 这一条是拿真库探出来的，不是想出来的

第一版一视同仁，于是真库 `#26` 渲染成：

```
↩ replaces (that block no longer holds): (cited block is no longer valid)
```

同一件事说两遍，⛔ 而且**丢掉了「它取代的是哪一块」** —— 那正是这一行存在的理由。
⭐ supersedes 指着退役块**本来就是正常状态**：退役正是这条关系自己写的
（`setBlockSupersession` 在这一档同时写 `stale_at`），marker 里那句「that block no longer holds」
已经把退役说出来了。⇒ **supersedes 保留预览，`cites` / `corrects` 收掉。**
这正是 Ocean 施工单规则 1「supersedes → retired：正常，不告警」在渲染层的对应。
