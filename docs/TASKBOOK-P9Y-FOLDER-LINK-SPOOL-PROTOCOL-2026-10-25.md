## 0. 一句话

让 Spool 的一个工作区连上电脑上的一个文件夹（代码仓库、论文文件夹都行；第二轮，见 §8）。Spool 能列出里面的文件、看出上次之后改了什么、读用户指定的几份「现状文件」。同时在文件夹根目录放一份 `SPOOL.md`，告诉在这个文件夹里工作的 AI：这个文件夹对应哪些 Spool 项目、冲突时谁说了算、什么时候去读、什么时候写回。

## 2. 评估：那三个大问题

### 2.1 先把 Flux 的事实摆清楚

- **Flux 仓库自己有一套很完整的现状记录。** README 顶上写当前计划在哪；`docs/WORK_PLAN_2026-10-02.md` 第 2 节是现行计划（10-24 按 10-21 的 proposal 改写），第 6 节是逐日状态；proposal 原文和最新交接在 `plans/dissertation/`，这个文件夹被 `.gitignore` 忽略、只在本机；旧东西挪进 `archive/<日期>/` 并在 `archive/README.md` 登记。仓库里的 AI 一直在认真维护这些。
- **研究方向至少换了三轮。** 09-26 的 R0 / E0 → 10-02 的 R1–R3（后训练、RFT、best-of-N）→ 10-21 的模式 A / B 比较加贴合度模型，不训练 MIDI-GPT。
- **Spool 里三个 Flux 项目记的内容本身没错，错在前提。** 它们记的是第二轮之前的计划，而 Spool 看不见仓库，不知道前提变了（第 203 条已核实）。10-25 第 204 条手动收了几条跟进行、重写了〈Flux〉的摘要。这一次是人补的，下一次方向再变还会一样。

### 2.2 问题一：能不能让 AI 自动写回、帮忙整理

**结论：完全自动、谁都不用管的写回做不到；但「不靠你记得」做得到。**

做不到的那一半：Spool 只在 AI 主动来调用它的时候才知道发生了什么。你在 Claude Desktop、Codex、VS Code 里的对话，Spool 一句都看不见，也没法主动去拿。不存在一个 Spool 自己在后台把三个客户端的结论收进来的办法。

做得到的那一半，靠三件事叠在一起：

1. **让 Spool 去读仓库，而不是等 AI 来写。** 仓库里的 AI 本来就在维护 WORK_PLAN、HANDOFF。这些文件一改，Spool 就知道仓库走到前面去了。现状不用写回 Spool，Spool 直接读。
2. **让每个客户端的 AI 知道什么时候写回一条。** `SPOOL.md` 写清楚几个时刻：方向变了、定了一件事、放弃了一条路、留下一个没解决的问题。每次一条，指着被推翻的旧块，进待审等你点。三个客户端都读得到它（§3.4）。
3. **忘了的时候看得见，也不再浪费额度。** Spool 记住上次跟仓库对齐是什么时候。之后现状文件改了，右栏、项目列表、任何 AI 读这个项目时都会看到「仓库在上次同步之后改了计划」。开着每周自动跟进的项目先停下，不再拿已经放弃的前提去查（§3.6）。

关于「帮我整理文档」：不建议让 AI 定期改写 Spool 里的旧块。8 月起的规矩是「写回只写这场对话产出、库里没有的东西」，整理会制造噪声，还会动你自己的记录。正确的形态是**标成历史**而不是改写：被推翻的块进待审，你点「取代」，旧块留着、在 pack 里标成历史。这套工具已经有了，就是更正 / 取代提议加待审。缺的只是有人在对的时机去提，也就是上面那三件。

### 2.3 问题二：对写代码的人，Spool 到底算什么

**结论：分工可以划得很清楚。「现在做什么、做到哪」以仓库为准；「为什么这样做、从哪来、外面怎么说、还有什么没定」在 Spool。**

- **仓库擅长的**：现行计划、进度、代码、交接。这些东西一天改好几次，由仓库里的 AI 维护。复制一份到 Spool 只会多一份会过期的进度，Flux 的问题就是这么来的。
- **Spool 擅长、仓库装不下的**：网页和论文的来源，以及读到它的日期；在聊天应用里想出来、从来没进过仓库的东西；做某个决定时考虑过又放弃的选项；要盯的外部事情，比如截止日期、会议、别人的回复；跨项目的东西，比如毕设、申请、课程放在一起看。

「回到代码库那一刻，Spool 的使命就完成了吗？」**不完全。** Flux 三个项目里有两个（导师沟通、深度调研）根本不是代码。接下来伦理申请、招募 6–10 位音乐人、文献综述、写论文，都会在仓库外面的对话里发生。Spool 的角色从「工作台」变成「背景资料 + 外部记忆」，并且要学会**对仓库让路**：和仓库现状冲突的内容是历史，不是现状。

边界的一条硬线：**Spool 不跟踪代码本身**，不看 diff、不读源码，只看仓库里写给人看的文档。这样既解决了 Flux 的过期，也不会让 Spool 变成另一个开发工具。

### 2.4 问题三：是不是走得太偏了

**结论：有偏的风险，而且偏的方向和你自己的大部分用法相反。P9Y 可以做成不加剧它的样子。**

证据（DISCOVERED-20261025-6）：

- 9-30 以来 24 个里程碑全部来自你一个人的用法，记录里没有一条外部用户反馈；
- 下载数 84，分不出多少是自测；
- 最近三个（P9T / P9U / P9V）都在要装命令行工具或填 key 的 AI 引擎那一层；
- 你自己库里 66 个项目约 50 个和写代码无关（申请、课程、毕设资料）。

所以真正的问题不是「功能太硬核」，而是**新功能越来越只服务「写代码、装了 CLI」这一种人，而这种人恰好是最不缺工具的**。

P9Y 怎么不加剧它：做成「连一个文件夹」，不是「连代码仓库」。论文文件夹（docx 加一份计划）、申请材料文件夹一样能连，现状文件就是论文计划或申请进度表。git 相关的几样（提交记录、`.git/info/exclude`、仓库里的 AI 说明文件）都是有就用、没有就跳过。

建议的后续顺序（要你拍板，不是已排期）：

1. P9Y 只做核心（§5 的 A 部分），外加两件便宜的：仓库变了先停自动跟进、文件改了重读；
2. 发一版；
3. **P10 之前先做 5–8 人的小范围试用**，就是 DISCOVERED-20261025-6 的建议：找申请季、写毕设的同学用 Mac 版，看第一天怎么用、卡在哪。这是产品验证，不碰营销闸门；
4. 看试用结果再定 P10 / P11，以及 P9Y 的「对照仓库」要不要做。

和原定计划的关系：`EXECUTION_POLICY.md` 没有要改的地方，产品仍是主线、研究第二、营销封着。第 3 步只是在 HANDOFF 路线图的 P10 前面插一段试用，属于 HANDOFF 层面的重排，要你点头。研究线那边，Flux 正好是「有害历史」的真实样本（DISCOVERED-20261025-7），本任务书不碰研究线。

## 3. 设计

### 3.1 「连接」是什么（Ocean 答 1）

参照 Claude Desktop：它的 Cowork 项目把本地文件夹放在项目的「Context」下面，用加号菜单选，macOS 会问一次授权，从同一个菜单移除。Spool 照这个形态，放在项目右栏最上面：

```
┌ 连接的文件夹 ─────────────────────────────┐
│ flux                          ~/flux      │
│ 上次同步 10-14 · 之后改了 2 份现状文件      │
│   docs/WORK_PLAN_2026-10-02.md      现状  │
│   plans/…/HANDOFF_2026-10-23.md     现状  │
│   另外 11 个文件有改动           展开 ▸   │
│ SPOOL.md    打开 · 让 AI 读到它            │
│ 已经对过了                  …（换 / 断开） │
└───────────────────────────────────────────┘

没连的时候只有一行：  连接文件夹…
```

- **一个项目最多连一个文件夹**；一个文件夹可以被好几个项目连（§3.5）。
- 用系统的选择框选文件夹。记路径，也记系统认这个文件夹的身份（`src-tauri/src/file_identity.rs` 那一套）。文件夹挪了照样跟着找到；找不到时和项目文件一样标清楚是哪一种（`src-tauri/src/file_follow.rs`）。
- **列哪些文件**：
  - 跳过以 `.` 开头的文件和文件夹，`.git`、`.venv`、`.env` 都在其中；跳过常见的生成目录：`node_modules`、`target`、`dist`、`build`、`__pycache__`、`venv`；
  - 是 git 仓库时，`.gitignore` 忽略的不列，**但文档类照列**（.md / .txt / .docx / .pdf / .rtf）。Flux 的 `plans/dissertation/` 被忽略了，可它正是最新计划所在；`data/` 里的 MIDI 不是文档，不列；
  - 最多看 20,000 项，超过就停下并在卡上说一句。
  - 依赖里现在没有遍历文件夹、认 `.gitignore` 的库。执行窗二选一：自己写一个够用的 `.gitignore` 子集，或者加 `ignore` 这个纯本地的库（ripgrep 用的那个，没有联网代码，加之前跑一次 `cargo tree` 确认，HANDOFF §10.7）。
- **看改动**：Spool 在「上次同步」那一刻记下每个文件的大小和修改时间，现状文件再加一个内容指纹。之后再看就能分出新增、改过、删掉。是 git 仓库时，顺带读 `.git/logs/HEAD` 里上次同步之后的提交标题。只读这一个文本文件，**不调用 git 程序**：没装开发者工具的 Mac 上调用 git 会弹安装框。
- **什么时候看**：和项目文件一样，只在这个项目在屏幕上、或者有 AI / 引擎来问的时候看。**不在后台持续监视**：不用系统的文件事件，不耗电，不多要授权。
- **现状文件**：连接时用户勾 1–3 份。Spool 按文件名推荐：README、HANDOFF、WORK_PLAN、PLAN、STATUS、ROADMAP、TODO，以及最近改过的 .md。文件名里带日期的（比如 `HANDOFF_2026-10-23.md`）当成一个系列，以后永远读同一个文件夹里同一前缀、日期最新的那一份。你的仓库都是按日期出新交接的。
- **AI 能读到什么**：文件列表和改动（只有路径和时间，没有内容），加上现状文件的正文。**不开放读文件夹里任意文件。** 仓库里的 AI 自己就能读文件；通过 Spool 来的（Claude Desktop 普通聊天、ChatGPT、Spool 自己的引擎）只需要现状。

### 3.2 `SPOOL.md` 放在哪、谁能改（Ocean 答 2）

- **位置**：文件夹根目录，文件名 `SPOOL.md`。和 README、CLAUDE.md、AGENTS.md 一个习惯，打开文件夹就能看到。不用 `.spool/` 这种隐藏文件夹，因为你要的是用户知道它在那里。
- **文件分两段**：
  - `<!-- spool:begin -->` 和 `<!-- spool:end -->` 之间是 Spool 写的。和「一键接入」往全局说明里写的那一段同一个做法（`src-tauri/src/mcp.rs` 的 `write_client_guidance`）；
  - 标记以外全是用户的，Spool 一个字都不动。第一次创建时在下面放一个标题「你自己的规矩」，之后就归用户。
- **用户改了 Spool 那一段怎么办**：Spool 记住自己上次写进去的内容的指纹。下次要更新时发现被改过，**不覆盖**，右栏提示「SPOOL.md 里 Spool 那一段你改过，要不要换成新的」，能看差别再决定。
- **Spool 什么时候重写自己那一段**：连上或断开项目、项目改名、项目设成私密、现状文件换了。**不会因为时间流逝或项目内容变化去改它**，里面没有实时的东西。
- **备份**：写之前的备份放在 Spool 自己的数据目录。不在仓库里留 `.bak`，那会被误提交。
- **跟不跟 git**（§4 第 2 题）：连接时问一次。推荐「只留在这台电脑」：Spool 往 `.git/info/exclude` 加一行 `SPOOL.md`。这是 git 自带的、只对本机生效、不会被提交的忽略清单，不碰仓库里的 `.gitignore`。理由：`SPOOL.md` 里有你的 Spool 项目名，而且只在装了 Spool 的这台电脑上有意义。Flux 的 CLAUDE.md、AGENTS.md 也是只留本机的。
- **断开时**：问「删掉 Spool 那一段 / 留着」。Spool 写进 CLAUDE.md、AGENTS.md、`.git/info/exclude` 的那几行，只在内容还和它写的一模一样时才撤掉。
- **这是 Spool 第一次往用户的文件夹里写东西。** `file_follow.rs` 开头写死的「用户的文件只看不写」要改成列出例外，只写这四处：`SPOOL.md`、`.git/info/exclude` 的一行、用户勾了的 CLAUDE.md 一行、用户勾了的 AGENTS.md 一行。每一处都要用户在连接时看到过。

### 3.3 `SPOOL.md` 里写什么（Ocean 答 3）

只写不变的规矩，实时情况让 AI 走 MCP 现读。完整样张见附录 A（以 Flux 为例）。结构：

1. **这是什么**：两句话。
2. **对应哪些 Spool 项目**：只写项目名，AI 用 `list_threads` 按名字找到 id。按工作区分组，标出主项目。**不写 id**，这是 MCP 的硬规矩，id 不进任何正文。
3. **谁说了算**：现状以这个文件夹为准，列出现状文件（系列文件写成「取最新的」）。Spool 里存的是来源、理由、聊天里的结论、没定的问题和要盯的事。**Spool 里和现状文件冲突的内容是历史，不是现状。**
4. **什么时候读 Spool**：开始一段涉及方向、计划、调研、对外沟通的工作之前，读一次项目概览；要找某个调研结论或来源时去搜；只是写代码不用读。
5. **什么时候写回，每次一条**：
   - 计划或方向变了：写一块「从什么变成什么、为什么」，指着被推翻的旧块提「取代」；
   - 定了一件事、过了一个门槛、放弃了一条路：写一块；
   - 这次没解决的问题：提一条跟进行；
   - Spool 在跟进的事仓库里已经不做了：收掉那一行（永久跟进行要告诉用户，不能收）；
   - AI 写的项目摘要和现状对不上：更新摘要；
   - 写完之后告诉 Spool「已经对过了」（§3.6 a 做了才有这一条）。
6. **不写什么**：代码、运行日志、仓库文档的复制、每次提交的流水、为了整齐去改旧块。
7. **私密项目**：只放一句通用的话「私密项目不会出现在这里」，不暗示有没有。
8. **怎么移除**。

语言跟界面语言走：中文界面写中文，其他写英文。和全局说明那一段一样。

**我比「只写规矩」多加的一条是第 3 节「谁说了算」。** 只写什么时候读、什么时候写的话，AI 读到 Spool 里一个旧块时还是不知道它和仓库谁对。Flux 的自动跟进就是这样拿旧前提去查的。把「冲突时仓库是现状、Spool 是历史」写成规矩，是这份文件里最值钱的一句。

### 3.4 仓库里的 AI 怎么读到它（Ocean 答 4）

连接的最后一步单独一页「让 AI 读到它」。三个选项都列出来，**默认都不勾**，用户自己选，可以多选：

| 选项 | 做了什么 | 管哪些客户端 | 代价 |
|---|---|---|---|
| 这个仓库的 CLAUDE.md 加一行 `@SPOOL.md` | Claude Code 的 CLAUDE.md 支持 `@文件` 导入，启动时自动把 SPOOL.md 一起读进去 | VS Code 里的 Claude Code；Claude Desktop 里的 Claude Code | 改了仓库里一个文件；CLAUDE.md 不存在时不建 |
| 这个仓库的 AGENTS.md 加一句「开工前先读 SPOOL.md」 | Codex 没有导入写法，只能写一句话 | Codex CLI、Codex 桌面版 | 同上；靠模型照做 |
| 全局说明里加一句「工作目录里有 SPOOL.md 就先读它」 | 改「一键接入」写在 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md` 里的那一段 | 以后连的所有文件夹都生效，不用每个仓库改 | 只对做过一键接入的客户端生效 |

另外始终显示一句可以复制的话：「这个文件夹连着 Spool，开工前先读根目录的 SPOOL.md」。给不读这些文件的客户端手动贴，比如 Claude Desktop 普通聊天、ChatGPT。

Claude Desktop 的 Cowork 读不读文件夹里的 CLAUDE.md，执行窗要实测一次再写进界面，不要猜。

反方向也要通：AI 从 Spool 这边进来时，`list_threads` 和项目概览就能看到这个项目连着哪个文件夹、SPOOL.md 在哪、仓库是不是走到前面去了（§3.8）。

### 3.5 「一个工作区连同一个仓库就共用一份」（Ocean 答 5，我定的）

**规矩：协议跟着文件夹走，不跟着项目或工作区走。**

- 一个文件夹 = 一份 `SPOOL.md` = 库里 `folders` 表的一行。这一行存路径、身份、git 那几处的选择、Spool 上次写进去的指纹、同步时的快照。
- 项目通过 `folder_links` 连上去：一个项目最多一个文件夹，一个文件夹可以有很多项目。
- 好几个项目连同一个文件夹，不管在不在同一个工作区，都写进同一份 `SPOOL.md`，按工作区分组。第一个连的是主项目，可以换。你说的「同一个工作区连同一个仓库」是这条规矩的一个特例，不需要单独处理。
- 第二个项目去连一个已经连着的文件夹时，跳过 git 和「让 AI 读到它」那两步，只说一句：「这个文件夹已经连着〈Flux〉，〈FLUX 导师沟通与汇报〉会加进同一份 SPOOL.md」。
- 判断是不是同一个文件夹：解析掉替身和符号链接之后的真实路径，加上系统身份。同一个就算一个。
- **嵌套**：已经连着 `~/flux`，又把 `~/flux/frontend` 连给另一个项目，允许。会有两份 SPOOL.md，连的时候提示一句；里面那份加一行「上层还有一份：../SPOOL.md」。在子文件夹里工作的 AI 读近的那份，和 CLAUDE.md、AGENTS.md 按目录就近的规矩一样。
- **为什么不按工作区连**：你库里大部分工作区（申请、课程）没有仓库；按工作区连，会让「工作区里哪个项目对应仓库的哪一块」说不清。按文件夹连，工作区共用是自然得到的。

### 3.6 更强的一步：同步游标

这是我提议加的，Ocean 没要求过。§4 第 1 题决定做哪几件。它回答的是「让各平台的数据零摩擦保持统一」。

**同步游标**：Spool 记住这个文件夹「上次和 Spool 对齐」那一刻的样子。之后现状文件变了，就说明仓库走到前面去了。

- 谁来推它：仓库里的 AI 写回之后调一下「已经对过了」（新工具，§3.8）；你在右栏点「已经对过了」；以后「对照仓库」的结果处理完也算。
- 在哪里看得到：右栏那张卡；`list_threads` 每个项目多一个数；项目概览的「需要注意」多一项。SPOOL.md 不写它，因为它是实时的。

挂在游标上的四件，可以分开做：

| 件 | 做什么 | 好处 | 代价 |
|---|---|---|---|
| a. 游标本身 | 上面那些 | 「忘了写回」在每个客户端、右栏都看得见；不花钱 | 屏幕上多一个数；多一个 MCP 写工具 |
| b. 仓库变了先停每周自动跟进 | 现状文件在上次同步之后改过的项目，自动跟进这周先不跑，右栏写一句为什么，对齐一次就恢复 | 10-24 那种「拿已经放弃的方向去查学院 GPU」直接没了（DISCOVERED-20261025-3）；不靠 AI 判断，规则是死的 | 你改一次 README 的计划段也会停一周跟进，要点一下「已经对过了」 |
| c. 挂上的文件改了重新抽正文 | 用到文件时比一下大小和修改时间，变了就重抽，右栏标「这个文件改过」 | 修 DISCOVERED-20261025-1：〈Flux〉挂的 7 个文件里 4 个是旧正文；论文 docx 一样受益，不只写代码的人 | 打开项目时多一次文件比对，很快 |
| d. 对照仓库 | 卡上一个按钮：把项目的摘要、置顶、跟进行、最近的块和现状文件一起发给引擎（一次请求、不带工具，和过期检测一样），找出被仓库推翻的块、前提已经没了的跟进行、对不上的 AI 摘要；结果落在过期检测那一页等你点 | 不靠任何客户端的 AI 记得写回，Spool 自己就能发现 Flux 那种过期；顺带修 DISCOVERED-20261025-2（过期检测拿文件当证据）和 -4（挪进 archive 当信号） | 引擎多一件活，10-16 定的「引擎只做周回顾和跟进」再扩一次；每次花额度；提示词和闸要重写、要真跑 |

我的推荐：**a、b、c 这一次做，d 等小范围试用之后再说。** a 和 b 是规则，不花钱，对 Flux 立刻有用；c 是一个对所有人都存在的 bug；d 是最强的一件，但它让引擎变重，正是 §2.4 说的那种方向，值得先看看外部用户要不要。

### 3.7 私密项目（Ocean 答 6）

- **私密项目不能连文件夹**（推荐，§4 第 3 题）。按钮灰掉，旁边一句「私密项目不连文件夹：连了之后仓库里的 AI 会知道它存在」。
- 已经连着的项目被设成私密：设的时候提示「这个项目连着 ~/flux，设成私密会断开」，确认后断开，并把它从 SPOOL.md 里拿掉。
- MCP 侧：文件夹相关的所有输出都只经过「非私密项目」那层视图（`mcp.rs` 约 1590 行的临时视图）。加金丝雀测试：私密项目的名字、它连过的路径，不出现在 SPOOL.md 和任何 MCP 输出里。

### 3.8 MCP 怎么变

| 工具 | 改什么 | annotations | 引擎拿不拿得到 |
|---|---|---|---|
| `list_threads` | 每个项目多 `folder`（短路径）和 `folder_changed_since_sync`（现状文件改了几份） | 只读，不变 | 能 |

## 4. 要 Ocean 拍板的四件

每件都写了好处和代价。不改就按推荐做。

**第 1 题　§3.6 的四件做哪几件（可多选）**

- **a 同步游标**（推荐做）。好处：你在三个客户端里哪边忘了写回，Spool 右栏和任何 AI 读这个项目时都会看到「仓库 10-21 改了计划，Spool 还停在 10-14」。代价：右栏多一行数字，MCP 多一个写工具。
- **b 仓库变了先停自动跟进**（推荐做）。好处：不会再出现 10-24 那样，每周自动去查已经不做的「学院 GPU 跑 RFT」。代价：你改一次 WORK_PLAN 的计划段，那个项目的自动跟进就停到你或 AI 点「已经对过了」为止。
- **c 文件改了重新抽**（推荐做）。好处：〈Flux〉里挂的 WORK_PLAN 不会再停在 10-02 那一版。代价：几乎没有。
- **d 对照仓库**（推荐先不做，试用后再定）。好处：完全不靠 AI 记得写回，按一下就能列出「这几块被仓库推翻了」。代价：Spool 自己的引擎多一件活，每按一次花一次额度；要重写提示词、真跑验证，工作量和 P9V 差不多。

**第 2 题　SPOOL.md 默认跟不跟 git**（两种都会在连接时让用户选，这里只定预选哪个）

- **只留在这台电脑**（推荐）。好处：仓库是公开的也不会把你的 Spool 项目名推上 GitHub；不动 `.gitignore`。代价：换一台电脑 clone 下来没有这份文件，要在那台电脑的 Spool 里重新连一次。
- **跟着提交**。好处：别的电脑、合作者 clone 下来就有。代价：项目名会进 git 历史；没装 Spool 的人看到这个文件没用。

**第 3 题　私密项目**

- **不能连**（推荐）。好处：最简单，不可能漏。代价：私密项目用不了「看文件夹改动」。
- **能连，但不进 SPOOL.md、MCP 也看不到**。好处：私密项目也能在右栏看到仓库改了什么。代价：仓库里的 AI 照着 SPOOL.md 写回时永远找不到这个项目，写回那一半对它没用；多一套要测的分支。

**第 4 题　要不要「现状文件」这个概念**

- **要，用户勾 1–3 份，Spool 推荐**（推荐）。好处：AI 和引擎只读这几份就知道现状，改动列表也能分出「计划变了」和「代码改了」；第 1 题的 b 和 d 都靠它。代价：连接时多一步勾选。
- **不要，只给改动列表**。好处：连接少一步。代价：AI 要自己从几十个改过的文件里猜哪份是计划；b 做不了，因为任何文件一改就停跟进会太频繁。
