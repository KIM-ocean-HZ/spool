### 1.1 为什么是这个形态（下次要改条目先读这一段）

⛔ **`HANDOFF-NEXT-2026-08-26` §2.2 预设的甲/乙/丙，一个都没中。** 08-29 查官方一手文档：

- `packages[].registryType` 实收 `npm` / `pypi` / `nuget` / `oci` / `mcpb`（另有 `cargo`）——
  **没有「本地二进制 / 自托管」这一类**，所以字面上的「甲」不存在；
- **但 `ServerDetail.required` 只有 `name` / `description` / `version`**，
  `packages` 和 `remotes` **都是可选的**；
- 官方文档里有一个例子标题就叫 **Server with Custom Installation Path**，
  正文写「嵌在应用里、没有独立包的 MCP server，用 `websiteUrl` 指向安装说明」，
  例子的 description 逐字是 **“MCP server embedded in a Desktop app”**。

⇒ **metadata-only 条目**，四个字段，零新工程，不碰任何红线。

### 1.2 `.mcpb` 那条路否掉了（⛔ 别再重想一遍）

`.mcpb` 能把二进制挂在 GitHub Release 上，看着像"一键装"。**否掉的理由在代码里**：
`mcp.rs:1277` 和 `mcp.rs:3717` 读写两条路都硬检查 `PRAGMA user_version`，不等就拒答 / 拒写，
而拒答那条的错误原文是「请把客户端配置指向**新版 Spool.app 里的执行文件**」——
mcpb 装出来的二进制不在 `Spool.app` 里，**产品自己的报错文案和这条安装路径打架**。
另外官方今天明写会装 `.mcpb` 的客户端只有 Claude Desktop。

⚠️ 但要说清楚：**这不是数据风险。** MCP 那侧只读连接是 `SQLITE_OPEN_READ_ONLY`，
写连接从不创建也从不迁移库（迁移只在 GUI）。2026-05-29 那次抹库是 GUI 的 `migrateSchema`，
⛔ 不是这条路。

### 1.3 ⭐ 名字的大小写是要紧的

Registry 的权限是按 GitHub 的 `user.Login` **原样**拼成 `io.github.{login}/*`，
匹配用 `strings.HasPrefix`，**大小写敏感，全程没有 ToLower**（读过 registry 的 Go 源码）。
canonical login 是 `KIM-ocean-HZ` ⇒ 条目名必须照这个大小写写。⛔ 以后重发别改成小写。
