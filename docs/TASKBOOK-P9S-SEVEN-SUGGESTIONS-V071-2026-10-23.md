### P9S-1 · 页面整体往上移（第 7 条）

- **现在**：`<main>`（`App.tsx`）是 `overflow-hidden` 的 —— 它仍然是一个滚动容器，脚本能把它滚走。10-17 加的柜子（`KnitDrawer`）合着的时候是 `absolute bottom-0 translate-y-full`，整个柜子藏在 `<main>` 底边下面，给了 `<main>` 一段「看不见但滚得到」的高度。块里的 `scrollIntoView({ block: 'center' })`（跳到某一块、查找、待审「去看」）在内层滚到底还不够居中时，会接着去滚 `<main>`，于是项目名被顶上去、输入框下面露出柜子那段空白。窗口一变大，`<main>` 能滚的距离变成 0，就复原了 —— 和「全屏之后消失」对得上。
- **要做**：先在离屏 WebKit 里复现（真组件 + 跳到最后一块，量 `<main>.scrollTop` 不是 0）；修法优先 `<main>` 改成 `overflow: clip`（不是滚动容器，脚本滚不动它），WKWebView / WebView2 都支持；复现脚本再跑一遍量到 0。
- **不做**：不改柜子的动画；不改 `scrollIntoView` 的调用方。
- **验收**：复现前后各一次读数写进回执；Ocean：跳到项目最后一块（右栏「关系待审」/ 查找命中最后一块）之后项目名还在、输入框下面没有空白。

### P9S-2 · 引用自动解除（第 2 条，第 171 条）

- **现在**：右栏「关系待审」列出「引用方还有效、被引的那一块已经不作数、关系不是取代、用户还没确认」的边（`listPendingRefReviews`，纯函数版 `refNeedsReview`）；三个动作长在引用方那一块下面（`RefReviewActions`）。真库现在 1 条：〈剩余推荐信〉#5 更正了 #4（#4 被 #9 取代）。
- **要做**：
  1. 一个函数把**符合那条判据**的边全部解除（只清引用方的关系：`ref_block_id` / `ref_kind` / `corrected_quote` / `ref_note`，⛔ 一个块都不删、⛔ 不碰被引块的退役状态）；
  2. 在每一次「让一块不作数」之后跑一次（同一个撤销步里：撤销退役时那几条引用一起回来），开机后跑一次（清掉已经挂着的）；
  3. 「关系待审」那一节和 `RefReviewActions` 删掉，相关文案、注释、i18n 键一并清掉（自己造成的孤儿要删）。
- **不做**：用户之前点过「保留为历史引用」的边（`ref_reviewed_stale_at` 对得上）不动 —— 那是他明确选的；`supersedes` 照旧不算。MCP 那一侧不改。
- **验收**：测试覆盖「退役一块 → 引用它的更正 / 引用被解除；撤销 → 回来；取代关系和已确认的不动」；Ocean：〈剩余推荐信〉右栏没有「关系待审」了，#5 上不再写「更正了 #4」。

### P9S-3 · 「最近」可展开（第 3 条）

- **现在**：`RecentSection` 固定 3 行（`RECENT_MAX = 3`）。
- **要做**：「最近」标题右边一个很轻的展开记号（和工作区标题同一种 chevron、同一种颜色，悬停才明显）；展开后同一套行样式，最多 10 个，区域最高约 6 行、里面自己滚动，左边缘和行高不变；再点收回 3 行。展开状态不存（重开就是 3 行）。
- **不做**：不改排序规则（捕捉目标在最前、其余按 `updatedAt`）；不加多选。
- **验收**：截图展开 / 收起两张；Ocean 手指：展开后滚动看得到更多，收起之后左栏和原来一模一样。

### P9S-4 · 绿点：AI 写进来的新块（第 1 条，第 176 条）

- **现在**：项目行的 4px 小圆点只表示状态（进行中 / 搁置 / 已完成）。AI 写的块认得出来：来源是 MCP 那一类（`MCP_SOURCE_PREDICATE` / `isMcpSource`）。
- **要做**：
  1. 「有没有新的」= 这个项目里**来源是 MCP 的块**里最新那一块的时间 > 这个项目「看过」的时间。用户自己的捕捉、手写都不算。待审里被他点「要」的块也是 MCP 来源，同样算（它们落进的那个项目他未必看过）。
  2. 「看过」记在数据目录新文件 `ai-seen.json`（`plugin-store`）：`{ baseline, seen: { 项目 id: 时间 } }`。第一次用这一版时 `baseline = 现在`，之前的块一律当看过 —— ⛔ 升级后不许满屏亮绿灯。文件丢了 = 重新从「现在」算（安全的那一边：不亮）。
  3. 块列表里一块 MCP 来源、比「看过」新的块**真的出现在屏幕上**（IntersectionObserver，露出一半以上），就把这个项目的「看过」推到那一块的时间。
  4. 项目行的小圆点在「有新的」时换成亮绿色（新 token，经典 / 深色 / 情人节各配一个），看过就回到状态色；`aria-label` 说「AI 写进来了新内容」。
  5. 一个项目**变成**「有新的」那一刻，它所在的工作区（连同上层）收着的话自动展开（写进 `expandedWorkspaceIds`）；只在变的那一刻展开一次，他再收起来就不再硬展开。
  6. 数据随「别处写进来」的那次重读一起刷新（`reloadOutsideWrites`），不另起轮询。
- **不做**：「最近」和工作区标题不加点（第 176 条）。不改库。
- **验收**：测试覆盖判定（基线、MCP 才算、看过推进）；Ocean：让 AI 往一个收着的工作区里的项目写一块 → 工作区自己展开、那一行的点是绿的 → 点进去、那一块出现在屏幕上 → 点回到原来的颜色；他自己捕捉一块不变绿。

### P9S-5 · 周回顾一个项目一张卡（第 5 条，第 172 条）

- **现在**：周回顾是一整段 Markdown（`engine_runs.result_text`），提示词（`WEEKLY_API_SYSTEM`，CLI 那条是 `weekly_review_prompt_text`）要求「一个项目一段、三行」，但标题写法不固定（真库最近一份是 `**标题**` 一行，也有 `## 标题`）。
- **要做**：
  1. 两条路的提示词都加上固定格式：每个项目以 `## 〈项目标题原样〉` 开头，下面三行 `- **做了什么**：…` / `- **还剩什么**：…` / `- **离截止还有几天**：…`；最后那句建议以 `## ` 之外的一段写在最后。只改格式那几句，其余字节不动（照 `DISCOVERED-20260923-2` 的测试写法：换回占位符后逐字节相等）。
  2. 前端一个纯函数把一份回顾拆成：开头（如果有）、若干张项目卡（标题 + 若干行「标签：内容」，认不出标签的行照原样画在卡里）、结尾那句。`## X` 和单独一行的 `**X**` 都认成项目标题，所以旧的回顾也能拆；一张卡都拆不出来就照现在整段画。
  3. 卡片：项目标题（库里有同名项目就能点，点了打开那个项目），三行用小标签 + 正文排好，「没设截止日期」这类照抄、不改字；结尾那句单独一行放在卡片下面。⛔ 不截字、不加省略号。
  4. DeepSeek 真跑一次验格式（付费，几分钱；按 §10.7 先写判定标准：每个项目一个 `## `，标题和库里一致），原始结果存进回执。
- **不做**：P10 的 JSON、建议动作按钮、更新时弹消息。
- **验收**：拆分函数的测试用真库最近三份回顾的格式各造一份；截图（新格式一张、旧格式一张）；Ocean 看周回顾页。

### P9S-6 · 跟进：每周自动、安静、结果要标出来（第 6 条，第 173 – 175 条）

- **现在**：右栏「跟进内容」下面有「联网搜索」按钮，点了用本机 CLI 跑一次 `follow_up`，结果走 `propose_blocks` 进待审，跑完的文字卡挂在右栏顶上；Spool 这边有去重闸（`siftProposals`）。AI 只能关「单次」的跟进行，永久跟进关不掉（`close_follow_up_item_json`）。真库 8 个进行中的项目有跟进行（21 行，8 行永久）。
- **要做**：
  1. **开关**：右栏「编辑」面板（`FollowUpPanel`）里加「每周自动查一次」，每个项目一个，**默认关**；存在这个项目的 `follow_up_state` JSON 里（加一个可选字段，老版本读到会忽略）。
  2. **自动跑**：沿用周回顾那个十分钟一次的检查（`useAutoMaintain` 的节奏和刹车）：开了开关、有在跟进的行、项目没完成 / 没归档 / 不是私密、引擎能联网（Claude Code / Codex，写入开关都开着、「显示 AI 功能」开着）、上次跑距今满 7 天、队列空 ⇒ 排一次，一次只排一个项目（最久没查的先）。开机那一刻不跑；失败后至少隔一小时再试。
  3. **安静**：右栏「跟进内容」只剩那几行 + 一行小字「上次查：10-22 · 带回 2 条，在待审里」/「上次查：10-22 · 没有新消息」；跟进的文字卡不再挂在右栏顶上，「联网搜索」按钮和最近一次的完整回复挪进「编辑」面板（二级界面）。
  4. **只有有效信息才进待审**：去重闸照旧；这次没有新东西 = 待审里什么都不出现。
  5. **标出是跟进的结果**：引擎跑 `follow_up` 时，MCP 那一侧知道这是跟进（引擎起 `spool --mcp` 时多带一个标记），`propose_blocks` 的批次来源写成「…跟进」；待审卡上写「跟进带回来的」，点「要」之后块头上有一个「跟进」的小标签（来源里带着，不改库）。
  6. **AI 可以关、可以提议换**：只在引擎的跟进运行里，`close_follow_up_item` 也能关永久跟进；跟进的提示词写明「这一条已经没用 / 有答案了就关掉，写一句交代；想换成更好的一条就用 `suggest_follow_up_item` 提，新的那条等用户点『要』」。聊天里的 AI 客户端规则不变。
  7. MCP 改动照 `mcp-tool-routing-required`：工具描述和路由文本要一致；跑 `the_engine_whitelist_is_every_spool_tool` 等现有守卫。
- **不做**：不改跟进行的表结构；不做「每个项目自己选频率」；不让聊天客户端关永久跟进。
- **验收**：测试覆盖「到期判定 / 默认关 / 私密和已完成不跑 / 引擎跑时能关永久跟进、聊天时不能」；截图右栏和「编辑」面板；Ocean 在一个项目上打开开关、点一次「联网搜索」（手动那次照样能跑）看待审卡上的标记。⚠️ 真跑一次跟进会用他的 Claude Code / Codex 额度 —— 跑之前问。

7. **页面上移**：在一个块很多的项目里，从右栏或查找跳到最后一块。项目名还在顶上，输入框下面没有空白。
